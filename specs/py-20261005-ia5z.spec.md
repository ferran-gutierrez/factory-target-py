# Expense CLI top categories

- **REQ-1** Running `python -m factory_target_py.expenses` with a readable expense CSV and `--top` followed by a valid positive integer `N` prints JSON that includes a `top_categories` key whose value is a JSON array, and omits `top_categories` when `--top` is not supplied.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** Each element of `top_categories` is a JSON object with exactly two string keys `category` and `total`, where `total` is the same two-decimal money string as the value for that category in the printed `category_totals` object (including when `--month` filters `category_totals`).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-3** `top_categories` is built from the same `category_totals` map shown in the success JSON (after any `--month` filtering), sorted by numeric total descending using the underlying decimal values, and when two categories share the same total, by ascending `category` using plain Python string comparison on the canonical category names (so for example `Banana` sorts before `apple` because uppercase `B` precedes lowercase `a` in ASCII order).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** The `top_categories` array contains at most `N` entries; when `N` is greater than the number of categories in `category_totals`, it lists every category; when `category_totals` is empty, `top_categories` is an empty array.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** When `--top 2` is supplied and three categories `Food`, `Travel`, and `Rent` have totals `10.00`, `10.00`, and `5.00` respectively in `category_totals`, `top_categories` is `[{"category": "Food", "total": "10.00"}, {"category": "Travel", "total": "10.00"}]` (tie order follows plain string comparison on `Food` vs `Travel`, not case-insensitive order).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** When `--top 10` is supplied and `category_totals` has only two categories, `top_categories` has length two and includes both categories with matching totals.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** A `--top` value is invalid if it is not a non-empty string of ASCII decimal digits with no sign or decimal point and `int(value)` is less than one; for invalid values including `0`, negative integers, numbers with a decimal point, or non-numeric text, the CLI writes a clear error message to stderr, prints nothing to stdout, and exits with status code `1`.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-8** Running `python -m factory_target_py.expenses` with `--top` as the last argument (no value following), a second `--top` flag when one was already parsed, or an unrecognized optional argument writes a usage message to stderr, prints nothing to stdout, and exits with a non-zero status code.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-9** Optional `--top`, `--month`, and `--budgets` flags may appear in any order after the expense CSV path; for the same files and flag values, permutations such as `--top 3 --month 2024-04 --budgets budgets.csv` and `--budgets budgets.csv --top 3 --month 2024-04` produce identical success JSON including the same `top_categories` derived from month-filtered `category_totals`.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-10** When `--top` is not supplied, successful CLI JSON keys and values match the behaviour immediately before this task for the same expense CSV and any combination of `--month` and `--budgets` flags (including absence of a `top_categories` key).
  `[@test] ../tests/test_expenses_cli.py`
