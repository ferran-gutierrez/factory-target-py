# Ruff line length 140

- **REQ-1** The repository root `ruff.toml` sets `line-length` to `140` (integer), and leaves `target-version`, `src`, and `[lint].select` unchanged from their values before this task.
  `[@test] ../tests/test_ruff_line_length.py`

- **REQ-2** With the project configuration loaded from the repository root, `ruff format` applied to a Python module containing a single assignment whose right-hand side is a string literal of exactly 130 ASCII characters on one physical line leaves that physical line intact (does not wrap or break the line solely for width).
  `[@test] ../tests/test_ruff_line_length.py`

- **REQ-3** From the repository root, `ruff check .` exits with code 0 and reports no violations for the checked tree.
  `[@test] ../tests/test_ruff_line_length.py`

- **REQ-4** From the repository root, `ruff format --check .` exits with code 0 and reports every Python file under `src/` and `tests/` as already formatted.
  `[@test] ../tests/test_ruff_line_length.py`

## Assumptions

- The deliverable for this task is updating repository-root `ruff.toml`; that path is listed in `contract.paths.checkDefinitions` and AGENTS.md normally forbids editing it, but this task exists solely to change ruff formatting width and downstream implementation is expected to modify `ruff.toml` as the configuration change (not `pyproject.toml` tool settings).
- Out of scope: adding or changing `[tool.ruff]` (or any non-dependency settings) in `pyproject.toml`; the factory sensitive-file rule allows dependency list changes only.
- No changes to expense importer behaviour, CLI output, or other application logic in `src/factory_target_py` are required when the existing tree already satisfies the wider limit; only configuration and verification tests are in scope unless a file fails REQ-3 or REQ-4 after the limit change.
- REQ-2 uses a synthetic one-line assignment in the test (not production source) to prove the configured limit is at least 130 characters wide, distinct from the previous default of 100.
