# Expense CLI output format

- **REQ-1** Running `python -m factory_target_py.expenses` with a readable expense CSV and no `--format` flag prints to stdout the same JSON object as before this task (including `category_totals`, `month_totals`, `errors`, optional `month` and `budget_alerts` when other flags apply) and exits with code 0.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** Running `python -m factory_target_py.expenses` with a readable expense CSV and `--format json` produces stdout byte-for-byte identical to the same invocation without `--format` for the same expense file and other flags.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-3** Running `python -m factory_target_py.expenses` with a readable expense CSV and `--format csv` prints to stdout only CSV text whose first line is exactly `category,total`, followed by one line per category in `category_totals` after any `--month` filtering, ordered by ascending category name using plain string comparison (not case-insensitive), each line `<category>,<total>` where `<total>` is the same two-decimal string that would appear in JSON `category_totals` for that category, with no other stdout content.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** For an expense CSV whose valid rows yield canonical categories `apple` and `Banana` with non-zero totals, `--format csv` lists the `Banana` line before the `apple` line because uppercase `B` precedes lowercase `a` under plain string comparison even though `apple` precedes `Banana` case-insensitively.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** When both `--month YYYY-MM` and `--format csv` are supplied, the CSV lines reflect `category_totals` restricted to that month; for example rows dated `2024-03-15` and `2024-04-01` both in category `Food` with amounts `5.00` and `7.00`, `--month 2024-04 --format csv` yields stdout `category,total\nFood,7.00\n` (not a `12.00` total).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** When `--format csv` is used and the expense CSV contains invalid data rows, the process exits 0 after a successful expense file read, prints no JSON to stdout, prints the CSV header and category lines for valid data, and writes one stderr line per import error formatted `line <n>: <reason>` using the same `line` and `reason` values as the JSON `errors` array would contain.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** Running `python -m factory_target_py.expenses` with `--format` as the last token (no value following), or with `--format` followed by any value other than `json` or `csv`, writes a usage message to stderr, prints nothing to stdout, and exits with status 1.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-8** Optional `--format` may appear in any order relative to `--month` and `--budgets` after the expense CSV path; equivalent flag orderings produce the same stdout for the same files and format value.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-9** When `--format csv` is supplied together with `--budgets`, unreadable expense or budgets paths, invalid budgets CSV after a successful read, or duplicate normalized budget categories still follow the same stderr and exit-code rules as JSON mode and print no CSV category totals to stdout on failure.
  `[@test] ../tests/test_expenses_cli.py`
