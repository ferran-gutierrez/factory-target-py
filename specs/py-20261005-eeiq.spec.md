# Expense CLI top categories

- **REQ-1** When `python -m factory_target_py.expenses` succeeds and `--top` is not supplied, the printed JSON object has no `top_categories` key and every other key and value matches the CLI behaviour defined before this task for the same expense CSV path and the same optional `--month` and `--budgets` arguments.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** When `--top` is followed by a valid positive integer `N` (see REQ-9), successful JSON includes a `top_categories` key whose value is a JSON array of at most `N` objects, each with string keys `category` and `total`.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-3** Each `top_categories` entry’s `category` is a key from the printed `category_totals` object and its `total` equals the corresponding `category_totals` string value (two decimal places), so the summary is built from the same category totals the output already shows, including when `--month YYYY-MM` filters those totals to one calendar month.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** `top_categories` is ordered by descending numeric total (compare totals as `decimal.Decimal` values equal to the two-decimal strings), and when two categories share the same total, by ascending `category` using plain string comparison (`str` ordering, so upper-case letters sort before lower-case letters).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** When the number of categories in `category_totals` is greater than `N`, `top_categories` contains exactly `N` entries; when the number of categories is less than or equal to `N`, it contains one entry per category; when `category_totals` is empty, `top_categories` is an empty array.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** For invalid `--top` values — zero, a negative integer, a value containing a decimal point, or any text that is not a positive integer written in decimal digits — the CLI writes a clear error message to stderr (non-empty, mentioning `--top`), prints nothing to stdout, and exits with status code 1.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** Running `python -m factory_target_py.expenses` with `--top` as the last argument (no value following), with duplicate `--top` flags, or with an unrecognized optional argument after the expense CSV path writes a usage message to stderr, exits with a non-zero code, and prints no success JSON to stdout.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-8** Optional `--month`, `--budgets`, and `--top` flags may appear in any order after the expense CSV path; the same files and flag values produce the same `category_totals`, `top_categories`, and (when `--budgets` is used) `budget_alerts` regardless of flag order.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-9** A `--top` argument is valid only when it consists solely of ASCII decimal digits with no leading sign and parses to an integer strictly greater than zero (for example `1` and `10` are valid; `0`, `-1`, `1.5`, `abc`, and an empty string are invalid).
  `[@test] ../tests/test_expenses_cli.py`
