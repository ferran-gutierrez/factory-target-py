# Expense CLI output format

- **REQ-1** When `python -m factory_target_py.expenses` is run with a readable expense CSV path and `--format` is omitted or set to `json`, stdout and exit behaviour match the expense CLI behaviour defined before this task for the same optional `--month` and `--budgets` arguments (JSON object on stdout, exit code 0 after a successful expense file read).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** When `--format csv` is supplied with a readable expense CSV, the process prints to stdout only CSV text whose first line is exactly `category,total`, followed by one line per entry in the post-filter `category_totals` map as `{category},{total}` where `{category}` is the map key and `{total}` is the same two-decimal string that would appear for that key in JSON `category_totals`; lines after the header are ordered by ascending category name using plain string comparison (`<` on Python `str` values, so upper-case letters sort before lower-case).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-3** When both `--format csv` and a valid `--month YYYY-MM` are supplied, the CSV body uses `category_totals` after the same month filtering applied in JSON mode (only spending in that month contributes); when `--month` is not supplied, CSV uses the full-import `category_totals`.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** When `--format csv` is supplied, each import validation error is written to stderr as exactly one line `line {n}: {reason}` where `{n}` and `{reason}` match the `line` and `reason` fields of the corresponding object in the JSON `errors` array that `--format json` would emit for the same expense file; no JSON is printed to stdout.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** After the expense CSV file is read successfully, the process exit code is 0 for both `--format json` (or omitted) and `--format csv`, including when the import produced one or more validation errors.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** When `--format` is given without a following value, or with a value other than `json` or `csv` (including an empty string), the CLI writes a usage message to stderr, prints nothing to stdout, and exits with status 1.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** Optional `--format` may appear in any order with `--month` and `--budgets` after the expense CSV path; for example `--format csv --month 2024-05` and `--month 2024-05 --format csv` produce the same filtered CSV for the same files.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-8** When `--format csv` is used with an expense CSV that yields at least two categories whose plain string sort order differs from case-insensitive lexicographic order (for example canonical keys `Banana` and `apple` with both present in `category_totals`), the CSV data lines appear in plain string ascending order (`Banana` before `apple`), not case-insensitive order.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-9** When `--format csv` is used with a readable expense CSV that contains invalid data rows, stderr includes one `line {n}: {reason}` line per import error, stdout contains only the CSV header and valid category total lines, and the exit code is 0.
  `[@test] ../tests/test_expenses_cli.py`

- Runtime code uses the Python standard library only; no new third-party dependencies.
- `pyproject.toml` cannot gain console script entry points; the CLI remains `python -m factory_target_py.expenses`.
