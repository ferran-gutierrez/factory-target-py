# Expense CLI output formats

- **REQ-1** Running `python -m factory_target_py.expenses <csv-file>` without `--format` or with `--format json` produces the existing JSON output with the same keys, values, error objects, and exit behavior as before this task.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** Running the CLI with `--format csv` and a readable expense CSV prints to stdout a CSV document whose first line is exactly `category,total`, followed by one line per category in ascending category order using plain string comparison, with each total formatted as the same two-decimal string used by JSON output.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-3** When `--month YYYY-MM` is supplied with `--format csv`, category totals include only valid rows in the selected month and the CSV output remains limited to the selected categories and their two-decimal totals.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** When `--format csv` is supplied and the expense CSV contains invalid rows, each error is written to stderr as one line in the form `line <n>: <reason>` using the same line number and reason that JSON errors would contain, no JSON is printed, and the valid category totals are still printed to stdout.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** When the input expense file is readable, both JSON and CSV formats exit with status 0, including when CSV-format output also reports invalid rows.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** When `--format` is supplied without a value, or with any value other than `json` or `csv`, the CLI writes a usage message to stderr, prints nothing to stdout, and exits with status 1.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** The `--format` option may be used together with `--month` and may appear in either order relative to `--month`; the selected format and month filtering are applied consistently.
  `[@test] ../tests/test_expenses_cli.py`

## Assumptions

- Supersedes py-20261004-6bjo REQ-13: the CLI prints a JSON object for every successful invocation becomes the CLI prints format-specific success output, with JSON as the default and category-total CSV when `--format csv` is selected.
- Supersedes py-20261004-6bjo REQ-14: only existing positional, `--budgets`, `--month`, and unrecognized-argument usage errors are invalid becomes missing or invalid `--format` values are also usage errors.
- Supersedes py-20261004-16e2 REQ-12: a readable budgets file always produces JSON including budget alerts becomes default JSON with budgets includes budget alerts while CSV format prints only category totals.
- Supersedes py-20261004-16e2 REQ-14: usage errors cover the existing CLI arguments becomes usage errors also cover missing or invalid `--format` values.
- CSV category ordering uses Python plain string ordering, so uppercase letters sort before lowercase letters; this intentionally differs from case-insensitive budget-alert ordering.
- CSV output contains category totals only, even when `--budgets` is supplied; budget alerts are not rendered in CSV.
- CSV error lines are emitted after successful input reading and do not change the successful exit status.
- `--format` is parsed as an order-independent optional flag alongside the existing `--month` and `--budgets` flags.
- Runtime code uses only the Python standard library; no new dependencies or console entry points are needed.
