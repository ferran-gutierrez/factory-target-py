# Expense CLI top categories

- **REQ-1** Running `python -m factory_target_py.expenses` with a readable expense CSV and no `--top` flag prints success JSON whose keys and values match the behaviour immediately before this task for the same positional path and any combination of `--month` and `--budgets` (in particular, no `top_categories` key).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** Running with a readable expense CSV and `--top` followed by a valid positive integer `N` prints success JSON that includes a `top_categories` key whose value is a JSON array.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-3** Each element of `top_categories` is a JSON object with exactly two string keys: `category` (an expense canonical category name) and `total` (that category’s amount as a JSON string with exactly two digits after the decimal point, using the same formatting as the corresponding entry in `category_totals`).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** The `top_categories` array is built from the same `category_totals` map included in that JSON payload (after any `--month` filtering applied to `category_totals`), so each listed `category`/`total` pair matches a key/value in `category_totals` and no category absent from `category_totals` appears.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** `top_categories` is ordered by descending numeric total (compare underlying `Decimal` values, not string order), and when two categories share the same total, by ascending `category` using plain lexicographic string comparison on the canonical category strings (Unicode code point order, so an upper-case letter sorts before a lower-case letter in the same position).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** When two categories tie on total, the category whose name sorts earlier under plain string comparison appears first in `top_categories`; for example totals `Travel` `10.00` and `travel` `10.00` yield `[{"category": "Travel", "total": "10.00"}, {"category": "travel", "total": "10.00"}]` because `"Travel" < "travel"`.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** The array length is at most `N`; when `N` is greater than or equal to the number of categories in `category_totals`, every category in `category_totals` appears exactly once.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-8** When `category_totals` is empty (including `--month` filtering that leaves no spending in that month), `top_categories` is an empty JSON array `[]`.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-9** A `--top` argument is invalid if it is not a base-10 unsigned integer written with ASCII decimal digits only (no sign, no decimal point, no other characters), or if its integer value is less than one; examples of invalid values are `0`, `-1`, `1.5`, and `abc`. For an invalid `--top` value the CLI writes a non-empty clear error message to stderr, writes nothing to stdout, and exits with status code `1`.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-10** Running with `--top` as the last token (no following value) writes a usage message to stderr, exits with a non-zero code, and prints no success JSON to stdout.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-11** When both `--month YYYY-MM` and `--top N` are supplied, `top_categories` reflects only categories and totals from the filtered `category_totals` for that month (not categories whose spending occurred only in other months).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-12** Optional `--top`, `--month`, and `--budgets` flags may appear in any order after the expense CSV path; the same files and flag values produce the same `category_totals`, `top_categories`, and other JSON fields regardless of flag order.
  `[@test] ../tests/test_expenses_cli.py`

## Assumptions

- Supersedes py-20261004-6bjo REQ-13: optionally `--month YYYY-MM` and/or `--budgets` followed by a budgets CSV path becomes optionally `--month YYYY-MM`, `--budgets` followed by a budgets CSV path, and/or `--top N` with a positive integer `N`, with JSON output including `top_categories` when `--top` is present as defined in this spec.
- Supersedes py-20261004-6bjo REQ-14: usage error on unrecognized optional arguments and missing or invalid `--month`/`--budgets` becomes the same usage cases plus `--top` without a following value; invalid `--top` numeric values use a dedicated stderr error message (not the general usage line) with exit code `1` and empty stdout per REQ-9 of this spec.
- Supersedes py-20261005-mwft REQ-9: optional `--month` and `--budgets` may appear in any order becomes optional `--month`, `--budgets`, and `--top` may appear in any order after the expense CSV path.
- Supersedes py-20261004-16e2 REQ-14: usage error on bad positional count, missing or invalid `--month`, or missing `--budgets` path becomes the same cases plus `--top` without a following value; invalid `--top` values follow this spec’s REQ-9 rather than the usage message.
- A valid `--top` value is a non-empty string of ASCII digits `0`–`9` whose integer value is at least `1` (leading zeros such as `01` are accepted and mean that integer value).
- Supplying `--top` more than once is a usage error (same pattern as duplicate `--month` or `--budgets`).
- Invalid `--top` stderr text is implementation-defined except that it must be non-empty and must not be success JSON; tests assert exit code, empty stdout, and non-empty stderr without requiring an exact message string.
- `top_categories` is omitted entirely when `--top` is not supplied; it is not present as `null`.
- Runtime code uses the Python standard library only; no new third-party dependencies.
- `pyproject.toml` cannot gain console script entry points; the CLI remains `python -m factory_target_py.expenses`.
