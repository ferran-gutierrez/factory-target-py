# Top expense categories

- **REQ-1** Running `python -m factory_target_py.expenses` with one readable expense CSV path and no `--top` option produces exactly the same JSON fields and values as before this feature, with no `top_categories` field.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** Running `python -m factory_target_py.expenses` with a readable expense CSV path and `--top N` accepts `N` only when it consists of one or more decimal digits and represents a positive integer; for valid input it adds a `top_categories` field to the successful JSON output as an array.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-3** With `--top N`, each `top_categories` item has exactly the fields `category` and `total`, where `category` is the category key from the displayed `category_totals` object and `total` is that category's amount represented as a string with exactly two decimal places.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** With `--top N` and category totals for `Food` equal to `12.00`, `Travel` equal to `30.00`, and `Books` equal to `20.00`, `top_categories` contains the first two items in the order `Travel`, `Books` when `N` is `2`, demonstrating that categories are ordered by total descending and limited to at most `N` items.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** When two displayed categories have equal totals, `top_categories` orders them by plain string comparison of their category names, so an uppercase name sorts before a lowercase name when their totals tie; for example tied `Zoo` and `apple` entries appear as `Zoo`, then `apple`.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** When `--top N` is larger than the number of displayed categories, the CLI includes every displayed category in `top_categories` rather than padding or failing.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** When `--top N` is supplied and the displayed category totals are empty, the CLI succeeds and includes `"top_categories": []` in the JSON output.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-8** When `--month YYYY-MM` and `--top N` are both supplied, `top_categories` is built from the month-filtered `category_totals` shown in the same output, not from categories or amounts belonging only to other months; for rows with `Food` totaling `5.00` in `2024-03` and `Travel` totaling `8.00` in `2024-04`, `--month 2024-04 --top 1` produces only `Travel` with total `"8.00"`.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-9** The `--top` option can be supplied alongside `--month` and `--budgets` in either established flag order, and a successful output retains the existing fields for those options while adding `top_categories`.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-10** When `--top` is followed by `0`, a negative integer, a value containing a decimal point, or any other non-digit text, the CLI writes a clear invalid-top error message to stderr, writes nothing to stdout, and exits with status 1.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-11** When `--top` is supplied without a following value, or when the option is supplied more than once, the CLI writes a usage message to stderr, writes nothing to stdout, and exits with a non-zero status.
  `[@test] ../tests/test_expenses_cli.py`

## Assumptions

- The option syntax is `--top N`, and optional flags remain order-independent as established by the existing `--month` and `--budgets` CLI behavior.
- `N` is parsed as a base-10 integer without signs, whitespace, decimal notation, or other numeric forms; values outside the implementation's supported Python integer range are not expected because Python integers are unbounded.
- The invalid-value error uses the clear message `invalid --top value: expected a positive integer`; missing or repeated `--top` uses the existing usage-message pattern.
- Top-category sorting uses `(-total, category)` with the category comparison performed by ordinary Python string ordering, so uppercase letters sort before lowercase letters and no case folding is applied.
- Top-category totals are formatted with the same two-decimal money serializer used by the existing CLI totals; no new runtime dependency or persistent storage is introduced.
- `top_categories` is added only when `--top` is present, including when its value exceeds the number of categories or when the selected month has no categories.
- End-to-end tests are out of scope because the contract does not apply E2E checks; subprocess-based CLI unit tests under `tests/` verify the command-line behavior.
