# Expense CLI top categories

- **REQ-1** Running `python -m factory_target_py.expenses` with a readable expense CSV and `--top` followed by a valid positive integer `N` prints success JSON that includes a top-level `"top_categories"` key whose value is a JSON array.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** Each element of `"top_categories"` is a JSON object with exactly two string keys `"category"` and `"total"`, where `"category"` is the expense canonical category name and `"total"` is that category’s amount formatted as a JSON string with exactly two digits after the decimal point (the same formatting as values in `"category_totals"`).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-3** `"top_categories"` is built from the same category totals map reflected in `"category_totals"` in the printed JSON (after any `--month` filtering), so each listed category’s `"total"` equals the string value in `"category_totals"` for that category name.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** `"top_categories"` is ordered by descending numeric total (compare the `Decimal` values behind the money strings), and when two categories share the same total, by ascending `"category"` using plain lexicographic string comparison (ASCII code point order, so an upper-case letter sorts before a lower-case letter in the same position).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** When `--top N` is supplied with valid `N`, `"top_categories"` contains at most `N` entries; when `N` is greater than the number of categories in the totals map, it contains every category exactly once.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** When `--top N` is supplied and the relevant `"category_totals"` object is empty (for example `--month` selects a month with no valid rows), `"top_categories"` is an empty JSON array and the process exits with code 0.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** When `--top` is not supplied, successful CLI JSON omits the `"top_categories"` key and every other key and value matches the behaviour defined before this task for the same expense CSV and the same optional `--month` and `--budgets` inputs.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-8** A `--top` value is invalid if it is not a non-empty string of ASCII digits whose integer value is at least 1 (rejecting `0`, negative signs, decimal points, letters, whitespace-only text, and empty values after the flag); in those cases the CLI writes a clear error message to stderr (not the generic usage line), writes nothing to stdout, and exits with status 1.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-9** When valid rows yield categories `apple` and `Banana` with the same total in the relevant totals map, `--top 2` lists `"Banana"` before `"apple"` in `"top_categories"` because plain lexicographic comparison places `"Banana"` ahead of `"apple"` when totals tie.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-10** Optional `--top`, `--month`, and `--budgets` flags may appear in any order after the expense CSV path; the same files and flag values produce the same `"category_totals"` and `"top_categories"` regardless of flag order.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-11** Running `python -m factory_target_py.expenses` with `--top` as the last argument (no value following), a duplicate `--top` flag, or any unrecognized optional token writes a usage message to stderr, exits with a non-zero code, and prints no success JSON to stdout.
  `[@test] ../tests/test_expenses_cli.py`
