# Expense top categories summary

- **REQ-1** The package exposes `compute_top_categories(category_totals: dict[str, decimal.Decimal], n: int) -> list[dict]` in `factory_target_py.expenses` that returns a list of dicts each with string key `category` and `decimal.Decimal` key `total`, containing up to `n` entries from `category_totals` ordered by descending `total` and, when two categories share the same total, by ascending `category` compared with standard string ordering on the canonical category names.
  `[@test] ../tests/test_expenses_top_categories.py`

- **REQ-2** When `category_totals` is `{"Travel": Decimal('15.00'), "Food": Decimal('15.00'), "Rent": Decimal('40.00')}` and `n` is `3`, `compute_top_categories` returns three dicts whose `category` values in order are `["Rent", "Food", "Travel"]` (not `["Rent", "Travel", "Food"]`, which would follow descending total but wrong tie order on `Food` vs `Travel`).
  `[@test] ../tests/test_expenses_top_categories.py`

- **REQ-3** When `category_totals` has only two categories and `n` is `5`, `compute_top_categories` returns both categories in the same descending-total then ascending-category order as when `n` is `2`.
  `[@test] ../tests/test_expenses_top_categories.py`

- **REQ-4** Running `python -m factory_target_py.expenses` with a readable expense CSV and `--top` followed by a valid positive integer `N` prints success JSON that includes `top_categories` as a JSON array of objects with string keys `category` and `total`, where `total` is a two-decimal money string, the array length is at most `N`, and its order matches `compute_top_categories` applied to the same `category_totals` map printed in the payload (after `--month` filtering when that flag is present).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** Running `python -m factory_target_py.expenses` with a readable expense CSV and no `--top` flag prints success JSON whose top-level keys are unchanged from the behaviour before this task for the same other flags (for example `category_totals`, `month_totals`, and `errors` only when neither `--budgets` nor `--month` is supplied), and omits `top_categories`.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** Running `python -m factory_target_py.expenses` with `--top` followed by `0`, a negative integer string, or a non-integer token such as `abc` or `2.5` writes a clear error message to stderr that identifies the invalid `--top` value, exits with a non-zero code, and prints no success JSON to stdout.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** Running `python -m factory_target_py.expenses` with `--top` as the last argument (no value following) writes a usage message to stderr and exits with a non-zero code.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-8** When `--month YYYY-MM` and `--top N` are both supplied, `top_categories` ranks only categories and totals from the filtered `category_totals` for that month; for example rows `2024-03-15,Food,A,5.00` and `2024-04-01,Travel,B,20.00` with `--month 2024-04 --top 2` yields `"top_categories": [{"category": "Travel", "total": "20.00"}]` and no `Food` entry.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-9** Optional `--top`, `--month`, and `--budgets` flags may appear in any order after the expense CSV path; for example `--top 1 --budgets budgets.csv` and `--budgets budgets.csv --top 1` produce the same `top_categories` and `budget_alerts` for the same files when other arguments match.
  `[@test] ../tests/test_expenses_cli.py`

## Assumptions

- A valid `--top` value is a decimal integer string with no fractional part that parses to an integer greater than zero (for example `"3"`); leading zeros such as `"03"` are accepted when they parse to a positive integer.
- Invalid `--top` values (zero, negative, or non-integer) use a dedicated stderr error line rather than the generic usage message; `--top` without a following token still uses the usage message like `--month` without a value.
- Duplicate `--top`, `--month`, or `--budgets` flags on one invocation are treated as CLI misuse and produce the usage message on stderr with a non-zero exit code.
- Tie-breaking on category name uses lexicographic order on the expense canonical category strings (same keys as in `category_totals`), not case-insensitive comparison.
- `compute_top_categories` is defined only for positive `n`; callers pass validated integers from the CLI or tests.
- When `category_totals` is empty, `top_categories` is an empty JSON array on success.
- Unreadable expense or budgets paths, invalid budgets CSV content, and invalid `--month` values keep the stderr and exit behaviour defined in earlier expense CLI specs; this task does not change those paths except when an invalid `--top` is detected before or instead of success JSON.
- Runtime code uses the Python standard library only; no new third-party dependencies.
