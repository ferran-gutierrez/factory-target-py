# Expense CLI output format

- **REQ-1** Running `python -m factory_target_py.expenses` with a readable expense CSV path and no `--format` flag prints to stdout the same JSON object as immediately before this task (including optional `--month` and `--budgets` behaviour) and exits with code 0.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** Running with `--format json` and a readable expense CSV prints to stdout the same JSON as REQ-1 for the same arguments and exits with code 0.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-3** Running with `--format csv` and a readable expense CSV whose valid rows yield category totals `apple` `1.00` and `Banana` `2.00` (expense-first canonical spellings) prints to stdout only the lines `category,total`, then `Banana,2.00`, then `apple,1.00` (plain string ascending order where uppercase letters sort before lowercase, not case-insensitive order), with no other stdout content, and exits with code 0.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** For `--format csv`, each `category,total` data line uses the same category key and two-decimal total string as the `category_totals` map in JSON output for the same import and filters (for example totals `"12.30"` not `12.3`).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** When `--format csv` and `--month YYYY-MM` are both supplied, stdout CSV category totals include only valid expense rows in that calendar month, matching the filtered `category_totals` in JSON mode for the same inputs (for example rows in `Food` totalling `5.00` in `2024-03` and `7.00` in `2024-04` with `--month 2024-04` yield a single data line `Food,7.00`).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** When `--format csv` and the expense CSV contains invalid data rows, the process exits with code 0 after a successful expense file read, prints no JSON to stdout, prints the CSV header and valid category total lines to stdout as in REQ-3 and REQ-4, and writes one stderr line per import error in the form `line <n>: <reason>` using the same integer line numbers and reason strings as the `errors` array in JSON mode (for example `line 2: empty category`).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** Running with `--format` as the last argument (no value following), with `--format` followed by any value other than `json` or `csv`, or with duplicate or conflicting `--format` options, writes a usage message to stderr, prints nothing to stdout, and exits with status 1.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-8** Optional `--format` may appear in any order with `--month` and `--budgets` after the expense CSV path; for example `--format csv --month 2024-04` and `--month 2024-04 --format csv` produce the same stdout CSV for the same files.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-9** When `--format csv` is supplied together with `--budgets` and readable CSV files, stdout remains category totals CSV only (no `budget_alerts` or other JSON); unreadable expense or budgets paths, invalid budgets CSV content after a successful read, and invalid `--month` values still follow the same stderr and exit-code rules as in JSON mode without printing success CSV to stdout.
  `[@test] ../tests/test_expenses_cli.py`

## Assumptions

- `--format json` is the default when the flag is omitted; only `json` and `csv` are accepted format values.
- CSV stdout uses Unix line endings (`\n`) and no trailing blank line after the last category row unless a future spec requires otherwise.
- Plain string category ordering for CSV compares Python string order on the expense canonical category keys (same keys as `category_totals` in JSON mode).
- `--format csv` does not change expense import validation, month filtering, or budget parsing; it only changes success stdout layout and moves per-row import errors from the JSON `errors` array to stderr lines.
- `pyproject.toml` cannot gain console script entry points; the CLI remains `python -m factory_target_py.expenses`.
- Runtime code uses the Python standard library only; no new third-party dependencies.
