# Ruff line length 140

- **REQ-1** `pyproject.toml` defines a `[tool.ruff]` table with `line-length = 140` (TOML integer).
  `[@test] ../tests/test_ruff_line_length.py`

- **REQ-2** When executed from the repository root, `python -m ruff check --show-settings` on any path under `src/` whose extension is `.py` reports `formatter.line_width = 140` and `linter.line_length = 140` in its output.
  `[@test] ../tests/test_ruff_line_length.py`

- **REQ-3** When executed from the repository root, `python -m ruff format --check .` exits with status code 0 (matching the factory contract `format` check).
  `[@test] ../tests/test_ruff_line_length.py`

- **REQ-4** When executed from the repository root, `python -m ruff check .` exits with status code 0 (matching the factory contract `lint` check).
  `[@test] ../tests/test_ruff_line_length.py`

## Assumptions

- The request means raising the project-wide Ruff line length from the current effective value of 100 to 140 for both formatting and `E501`-style line-length linting, not changing unrelated Ruff rules or `target-version`.
- Ruff resolves settings from the repository root `ruff.toml` when present; that file currently sets `line-length = 100` and therefore overrides any `[tool.ruff]` entry in `pyproject.toml` until the root value is also 140. REQ-2 through REQ-4 depend on the effective line length being 140; updating root `ruff.toml` is required for those requirements but that path is listed under `contract.paths.checkDefinitions` and is outside `contract.paths.allowed`, so implementation is assumed to include a coordinated update to root `ruff.toml` (or a contract path exception for this task) in addition to the allowed `pyproject.toml` change in REQ-1.
- No existing feature spec defines line-length behaviour; no earlier spec REQ or assumption bullets are superseded by this task.
