# Expense CLI output formats

- **REQ-1** Running `python -m factory_target_py.expenses` with a readable expense CSV and no `--format` option prints the existing JSON payload to stdout, and `--format json` produces the same payload for the same `--month` and `--budgets` arguments; both invocations exit with status 0 after the input file is read.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** Running `python -m factory_target_py.expenses` with a readable expense CSV and `--format csv` prints to stdout a CSV document whose first line is exactly `category,total` and whose remaining lines contain only category totals formatted with exactly two decimal places; for categories `apple` and `Banana`, the lines appear as `Banana,<total>` followed by `apple,<total>` because ordering uses plain case-sensitive string comparison.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-3** In CSV format, category totals are restricted to the month supplied by `--month YYYY-MM`; when the selected month has no valid spending, stdout contains only the `category,total` header line.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** In CSV format, every invalid expense row is reported on stderr in input order as exactly one line `line <n>: <reason>` using the same line number and reason produced by JSON errors, while stdout contains the category-total CSV and no JSON.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** Any `--format` value other than `json` or `csv`, and `--format` without a following value, writes a usage message to stderr, writes nothing to stdout, and exits with status 1.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** The `--format` option can be combined with `--month` and `--budgets` in either order after the expense CSV path; CSV output still contains only category totals, while JSON output retains its existing month and budget-alert fields.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** In both JSON and CSV formats, a readable expense file containing invalid rows still results in exit status 0; the invalid rows are represented in JSON errors or reported on CSV stderr according to the selected format.
  `[@test] ../tests/test_expenses_cli.py`

## Assumptions

- Supersedes py-20261004-6bjo REQ-13: one expense CSV path with optional `--month` and `--budgets` prints a JSON object becomes one expense CSV path with optional `--month`, `--budgets`, and `--format json|csv`, where JSON is the default and the selected format is printed.
- Supersedes py-20261004-6bjo REQ-14: usage errors cover missing or invalid month and budgets arguments becomes usage errors also cover missing or invalid format arguments.
- Supersedes py-20261004-6bjo assumption: CLI JSON output encodes money totals as two-decimal strings; error objects use `"line"` and `"reason"` keys only. becomes JSON remains the default output with two-decimal money strings and JSON error objects, while CSV output contains only category totals and reports invalid rows on stderr.
- CSV rows use the category spelling retained by the existing expense importer and totals use the existing Decimal quantization and ROUND_HALF_UP formatting rules.
- CSV output ends with a newline, uses comma delimiters without a separate quoting policy for category names, and writes no header or data other than the category-total document.
- `--format` accepts one value and follows the existing order-independent optional-flag parsing convention; repeated or unrecognized options are usage errors.
- Budget files are still read and validated when `--budgets` is supplied in CSV format, but budget alerts are not included in CSV stdout.
- End-to-end tests are out of scope because the contract does not apply E2E checks; CLI subprocess tests under `tests/` cover the behavior.
- Runtime code uses the Python standard library only; no new third-party dependencies are needed.
