# Expense CLI top categories

- **REQ-1** Running `python -m factory_target_py.expenses` with a readable expense CSV and no `--top` flag prints success JSON that omits the `top_categories` key and matches the keys and values defined by earlier expense CLI requirements for the same positional path and any supplied `--month` and/or `--budgets` flags.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** Running `python -m factory_target_py.expenses` with `--top` followed by a positive integer `N` prints success JSON that includes `top_categories` as a JSON array; each element is an object with string keys `category` and `total`, where `category` is an expense canonical category string from the CLI’s `category_totals` map and `total` is that category’s total formatted as a two-decimal money string using the same rules as `category_totals` values.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-3** The `top_categories` array lists at most `N` entries taken from the same `category_totals` map printed in the JSON (after any `--month` filtering), ordered by descending `total` compared as `decimal.Decimal` values and, when two categories share the same total, by ascending `category` using lexicographic string order on the canonical category names; for example with totals `Alpha` `10.00`, `Zoo` `10.00`, and `Mid` `5.00`, `--top 3` yields `top_categories` category names `["Alpha", "Zoo", "Mid"]` in that order (not `["Zoo", "Alpha", "Mid"]`, which would break the tie-break rule).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** When `--top N` is supplied and `N` is greater than the number of categories in the filtered `category_totals` map, `top_categories` includes every such category once, still ordered by REQ-3 rules; for three distinct categories and `--top 10`, the array length is `3`.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** When `--top` is followed by `0`, a negative integer token (for example `-1`), or a token that is not a base-ten positive integer (for example `abc` or `2.5`), the CLI writes a clear error message to stderr that mentions `--top`, exits with a non-zero code, prints no success JSON to stdout, and does not print a Python traceback on stderr.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** Running `python -m factory_target_py.expenses` with `--top` as the last token (no value following) or with a duplicate `--top` flag writes a usage message to stderr, exits with a non-zero code, and prints no success JSON to stdout.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** When both `--month YYYY-MM` and `--top N` are supplied, `top_categories` ranks only categories and totals from the month-filtered `category_totals` printed in the same JSON; for example rows `2024-03-01,Food,A,5.00` and `2024-04-01,Travel,B,9.00`, `--month 2024-04 --top 1` yields `"category_totals": {"Travel": "9.00"}` and a one-element `top_categories` list whose `category` is `Travel`.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-8** Optional `--month`, `--budgets`, and `--top` flags may appear in any order after the expense CSV path; for the same readable files and flag values, permutations such as `--top 2 --budgets b.csv --month 2024-05` and `--month 2024-05 --top 2 --budgets b.csv` produce identical success JSON (including the same `top_categories` ordering when `--top` is present).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-9** When `--top N` is supplied together with `--budgets`, success JSON includes both `budget_alerts` and `top_categories`; `top_categories` still follows REQ-3 ordering from `category_totals` and is independent of budget alert ordering.
  `[@test] ../tests/test_expenses_cli.py`

## Assumptions

- `top_categories` is omitted entirely when `--top` is not supplied; existing JSON keys (`category_totals`, `month_totals`, `errors`, optional `month`, optional `budget_alerts`) are unchanged aside from adding `top_categories` when requested.
- Positive integer parsing accepts optional leading zeros in the token (for example `--top 02` means `N` is `2`).
- Tie-breaking for equal totals uses case-sensitive lexicographic order on expense canonical category strings, not case-insensitive comparison.
- Invalid `--top` values use a dedicated stderr error line mentioning `--top`, distinct from the generic usage message used for missing flag values or duplicate flags.
- Unreadable expense or budgets paths and invalid budgets CSV content keep the stderr and exit behaviour defined in earlier expense CLI specs, regardless of whether `--top` is present.
- Optional flags remain order-independent; `pyproject.toml` cannot gain console script entry points; runtime code uses the Python standard library only.

- Supersedes py-20261004-6bjo REQ-14: usage error on missing or invalid `--month` and unrecognized optional arguments becomes usage error also on `--top` without a following value (invalid `--top` numeric values use a dedicated `--top` error message per this spec).
