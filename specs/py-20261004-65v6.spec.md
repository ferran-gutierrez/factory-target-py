- **REQ-1** The package exposes `parse_expense_csv(csv_text: str)` returning a result with `totals_by_category` (mapping category name to summed amount), `totals_by_month` (mapping `YYYY-MM` to summed amount), and `errors` (a list of records each with integer `line` and string `reason`).
  `[@test] ../tests/test_expense_importer.py`

- **REQ-2** The first line of `csv_text` is a header row; data rows start on line 2. The header must include columns named `date`, `category`, `description`, and `amount` (matched case-insensitively). Extra columns are ignored.
  `[@test] ../tests/test_expense_importer.py`

- **REQ-3** A data row is valid when `date` is a real calendar date in `YYYY-MM-DD` form, `category` and `description` are non-empty after trimming surrounding whitespace, and `amount` parses to a decimal number strictly greater than zero.
  `[@test] ../tests/test_expense_importer.py`

- **REQ-4** Each valid row adds its parsed `amount` to `totals_by_category` under the trimmed `category` and to `totals_by_month` under the row date’s `YYYY-MM`.
  `[@test] ../tests/test_expense_importer.py`

- **REQ-5** When `date` is missing, blank after trim, not in `YYYY-MM-DD` form, or not a real calendar date, the row is skipped and `errors` includes an entry whose `line` is the row’s 1-based line number in `csv_text` and whose `reason` describes the date problem.
  `[@test] ../tests/test_expense_importer.py`

- **REQ-6** When `category` or `description` is missing or blank after trim, the row is skipped and `errors` includes an entry with that row’s line number and a reason naming the empty field.
  `[@test] ../tests/test_expense_importer.py`

- **REQ-7** When `amount` is missing, blank after trim, not a decimal number, or less than or equal to zero, the row is skipped and `errors` includes an entry with that row’s line number and a reason describing the amount problem.
  `[@test] ../tests/test_expense_importer.py`

- **REQ-8** When a data row cannot supply one or more required columns (including a malformed CSV row with too few fields), the row is skipped and `errors` includes an entry with that row’s line number and a reason indicating missing or invalid columns.
  `[@test] ../tests/test_expense_importer.py`

- **REQ-9** CSV input containing only a valid header row yields empty `totals_by_category`, empty `totals_by_month`, and an empty `errors` list.
  `[@test] ../tests/test_expense_importer.py`

- **REQ-10** For CSV text with multiple valid and invalid data rows, valid rows contribute to both total maps, invalid rows appear in `errors` with distinct line numbers and reasons, and no invalid row affects totals.
  `[@test] ../tests/test_expense_importer_mixed.py`

- **REQ-11** A console script entry point registered in `pyproject.toml` reads expense CSV from a file path argument when provided, otherwise from standard input, calls `parse_expense_csv` on the full text, and prints human-readable category totals, month totals, and per-line errors to standard output with exit code 0 on success.
  `[@test] ../tests/test_expense_importer_cli.py`

## Assumptions

- Amounts are summed using `decimal.Decimal` (or equivalent exact decimal arithmetic) and exposed in the result as decimal values comparable to expected totals in tests.
- Comma is the field delimiter; standard CSV quoting rules apply via the standard library `csv` module.
- Completely blank lines in the file are ignored and do not produce error entries or affect line numbering for subsequent rows (physical line numbers still reflect the original `csv_text`, including blank lines).
- The CLI output format is not fixed beyond being human-readable and including each category total, each month total, and each error’s line number and reason.
- The console script name is `import-expenses` unless project conventions require a different setuptools entry-point name consistent with the package name.
