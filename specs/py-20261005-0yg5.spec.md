# Expense CLI top categories

- **REQ-1** Running `python -m factory_target_py.expenses` with a readable expense CSV and no `--top` flag prints success JSON whose keys are exactly those defined before this task for the same combination of other optional flags (`--month`, `--budgets`); in particular `top_categories` must not appear.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** Running with `--top` followed by a valid positive integer `N` and a readable expense CSV on success adds `"top_categories"` to the JSON payload as a JSON array.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-3** Each object in `top_categories` has exactly the keys `"category"` and `"total"`; `"category"` is the category name string from `category_totals` and `"total"` is the same two-decimal money string as the corresponding entry in `category_totals`.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** `top_categories` is built from the same category totals reflected in `category_totals` after any `--month` filtering; for example, with rows `2024-03-01,Food,A,5.00` and `2024-04-01,Travel,B,7.00`, `--month 2024-04 --top 1` yields `"category_totals": {"Travel": "7.00"}` and `"top_categories": [{"category": "Travel", "total": "7.00"}]`.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** `top_categories` is ordered by descending numeric total (compare the decimal values of the `"total"` strings); when two categories share the same total, the one whose `"category"` string is smaller under plain lexicographic comparison (character-by-character Unicode code point order, so uppercase letters sort before lowercase) appears earlier in the array.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** The array length is at most `N`; when more than `N` categories exist in `category_totals`, only the first `N` categories in the order from REQ-5 are included.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** When `N` is greater than or equal to the number of categories in `category_totals`, `top_categories` lists every category in `category_totals` exactly once (for example three categories and `--top 100` yields three objects).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-8** When `category_totals` is empty (for example `--month` on a month with no valid rows), `top_categories` is the empty JSON array `[]`.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-9** A `--top` argument value is valid only when it is a non-empty string consisting solely of ASCII decimal digits (`0`–`9`) and `int(value) >= 1`; values such as `0`, `-1`, `1.5`, and `abc` are invalid.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-10** For an invalid `--top` value (REQ-9), the CLI writes a clear, non-empty error message to stderr that is not the usage banner, prints nothing to stdout, and exits with status `1`.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-11** When `--top` is the last command-line token with no following value, or `--top` appears more than once, the CLI writes a usage message to stderr and exits with a non-zero status without printing success JSON to stdout.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-12** With expense rows putting `10.00` in category `Zebra` and `10.00` in category `apple`, `--top 2` lists `Zebra` before `apple` in `top_categories` (equal totals, tie broken by plain ascending category name where `"Zebra"` precedes `"apple"`).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-13** Optional `--top`, `--month`, and `--budgets` flags may appear in any order after the expense CSV path; the same files and flags in different orders produce identical `category_totals`, `top_categories`, and other JSON fields.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-14** When `--budgets` is also supplied, success JSON still includes `budget_alerts` and each `top_categories` entry still follows REQ-3 through REQ-7 for the same `N`.
  `[@test] ../tests/test_expenses_cli.py`

## Assumptions

- Supersedes py-20261004-6bjo REQ-13: optionally `--month YYYY-MM` and/or `--budgets` followed by a budgets CSV path becomes optionally `--month YYYY-MM`, `--top N`, and/or `--budgets` followed by a budgets CSV path, with JSON output including `top_categories` when `--top` is present.
- Supersedes py-20261004-6bjo REQ-14: `--month` without a following value, an invalid `--month` value, or unrecognized optional arguments writes usage becomes the same plus `--top` without a following value writes usage; invalid `--top` values use a dedicated stderr error per REQ-10 of this spec rather than the usage banner.
- Supersedes py-20261004-16e2 REQ-12: prints JSON that includes the keys from REQ-11 plus `budget_alerts` and `"month"` when `--month` is present becomes includes those keys plus `top_categories` when `--top` is present.
- Supersedes py-20261004-16e2 REQ-14: `--month` without a following value or invalid `--month` value writes usage becomes also `--top` without a following value writes usage; invalid `--top` value handling is defined in this spec.
- Supersedes py-20261005-mwft REQ-5: When `--month` is not supplied, successful CLI JSON keys and values match the behaviour before this task becomes when neither `--month` nor `--top` is supplied, successful CLI JSON keys and values match the behaviour before this task (no `top_categories` key).
- Supersedes py-20261005-mwft REQ-11: unreadable paths regardless of whether `--month` is present becomes unreadable expense or budgets paths behave the same regardless of whether `--month` or `--top` is present; invalid `--top` values are rejected before success JSON is printed.
- Supersedes py-20261005-kj6f REQ-9: Without `--month`, CLI usage and file-error behaviour unchanged becomes without `--top`, existing CLI usage, file-error, and money-string JSON rules stay unchanged; when `--top` is used, each `top_categories` `"total"` is a two-decimal money string consistent with `category_totals`.
- Supersedes py-20261005-3462 REQ-6: When `--month` is supplied together with `--budgets`, unreadable paths and invalid budgets CSV behaviour becomes the same unreadable-path and invalid-budgets rules when any combination of `--month`, `--top`, and `--budgets` is present.
- Supersedes py-20261005-lwd5 assumption: other CLI, validation, decimal, and month-filter behaviour stays unchanged except unreadable paths becomes the same except unreadable paths and the optional `--top N` summary defined in this spec.
- Valid `--top` values allow leading zeros (for example `007` means `N` is 7).
- The usage message shown for CLI misuse includes `[--top N]` alongside existing optional flags once `--top` appears in the implementation’s documented usage strings.
- `top_categories` ordering uses plain string comparison on category names for ties, not case-insensitive comparison (distinct from budget alert category ordering).
- Runtime code uses the Python standard library only; no new third-party dependencies.
- End-to-end tests are out of scope (`contract.e2e.applies` is false); behaviour is covered by unit-style subprocess tests under `tests/`.
