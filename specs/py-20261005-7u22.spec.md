# Expense CLI output formats

- **REQ-1** Running `python -m factory_target_py.expenses <csv-file>` with `--format` omitted or set to `json` prints the same JSON payload and values as the existing CLI for the same expense file and optional `--month` or `--budgets` arguments, and exits with status 0 when the expense file is read successfully.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** Running the expenses CLI with `--format csv` prints to stdout a CSV whose first line is exactly `category,total`, followed by one line per category total, with categories ordered by ascending plain string comparison and each total formatted as the same two-decimal string used by JSON output.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-3** When `--format csv` and `--month YYYY-MM` are supplied, the CSV category totals include only valid expense rows from that month, while the default or explicit `json` format retains the existing month-filtered JSON behaviour.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** When `--format csv` is supplied, every invalid expense row from the full input file is reported to stderr as one line exactly `line <n>: <reason>`, using the importer's line number and reason, and no JSON is printed to stdout.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** When the expense file is read successfully, both JSON and CSV formats exit with status 0 even when the input contains invalid rows; CSV output still contains the category totals for valid rows and reports the invalid rows on stderr.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** When `--format` has no following value or has any value other than `json` or `csv`, the CLI writes a usage message to stderr, writes nothing to stdout, and exits with status 1.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** CSV output uses plain case-sensitive string ordering for category names, so categories whose names differ only by case are ordered according to normal string comparison rather than case-insensitive comparison.
  `[@test] ../tests/test_expenses_cli.py`

## Assumptions

- `--format` is an order-independent optional flag alongside `--month` and `--budgets`, defaults to `json`, and applies only to the final output serialization.
- CSV format emits only category totals, so it omits the JSON month field, errors array, and budget-alert array from stdout; existing input reading, validation, month filtering, and budget parsing remain in effect.
- CSV invalid-row diagnostics are emitted after the full expense file is imported, preserving the importer's existing validation order and error records.
- Runtime code uses the Python standard library only; no new third-party dependencies are needed.
- Supersedes py-20261005-mwft REQ-1: month-filtered CLI output always prints JSON with a top-level month field when `--month` is supplied becomes JSON output retains that field while CSV output emits category totals only.
- Supersedes py-20261005-mwft REQ-5: successful CLI JSON keys and values are unchanged when `--month` is absent becomes that JSON compatibility applies when `--format` is omitted or `json`, while CSV emits category totals only.
- Supersedes py-20261005-mwft REQ-10: month-filtered output always carries all import errors in a JSON errors array becomes JSON carries the errors array and CSV reports the same errors on stderr.
- Supersedes py-20261004-16e2 REQ-14: usage errors cover positional arguments, `--budgets`, and `--month` misuse becomes usage errors also cover missing or invalid `--format` values.
- Supersedes py-20261005-lwd5 assumption: Budget alert ordering uses ascending `month` then ascending `category` compared case-insensitively on the expense canonical strings in each alert; other CLI, validation, decimal, and month-filter behaviour stays unchanged except unreadable expense or budgets paths report a single stderr line with the path string and no traceback. becomes Budget alert ordering uses ascending `month` then ascending `category` compared case-insensitively on the expense canonical strings in each alert; CLI behaviour stays unchanged except for the separately specified `--format` output option and unreadable expense or budgets paths reporting a single stderr line with the path string and no traceback.
