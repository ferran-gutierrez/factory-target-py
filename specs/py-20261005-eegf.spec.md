# Expense CLI output format

- **REQ-1** Running `python -m factory_target_py.expenses` with a readable expense CSV and no `--format` flag prints to stdout the same JSON object as immediately before this task for the same positional path and any combination of `--month` and `--budgets` flags (default output format is JSON).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** Running `python -m factory_target_py.expenses` with `--format json` and a readable expense CSV prints to stdout the same JSON as REQ-1 for the same inputs.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-3** Running `python -m factory_target_py.expenses` with `--format csv` and a readable expense CSV writes to stdout only CSV text whose first line is exactly `category,total`, followed by one line per category present in the filtered `category_totals` map formatted as the category name, a comma, and the total string with no spaces, where each total is the same two-decimal string that would appear under that category key in JSON output, with categories ordered ascending by plain string comparison on the category name (ASCII lexicographic order, so an upper-case letter sorts before a lower-case letter).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** For expense rows whose first valid category in file order is `Banana` with amount `1.00` and another valid row has category `apple` with amount `2.00`, `--format csv` lists the `Banana` line before the `apple` line (not `apple` before `Banana`, which case-insensitive ordering would produce).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** When `--month YYYY-MM` is supplied together with `--format csv`, the CSV lines reflect the same filtered category totals as `"category_totals"` in JSON output for that month (for example rows in `Food` totalling `5.00` in March and `7.00` in April yield only `Food,7.00` when `--month 2024-04` is used).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** With `--format csv`, each import validation error is written to stderr as exactly one line starting with `line `, then the line number, then `: `, then the reason string, using the same integer line number and reason string as the corresponding object in the JSON `errors` array; stdout contains no JSON and only the CSV from REQ-3; when the expense file was read successfully the exit code is 0 even when errors are present.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** With `--format json` or default format, a readable expense CSV that contains invalid rows still exits with code 0 after a successful read, with invalid rows listed only in the JSON `errors` array on stdout as before this task.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-8** Running `python -m factory_target_py.expenses` with `--format` followed by any value other than `json` or `csv` (for example `--format xml`) writes a usage message to stderr, prints nothing to stdout, and exits with status 1.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-9** Running `python -m factory_target_py.expenses` with `--format` as the last token (no value following) writes a usage message to stderr, prints nothing to stdout, and exits with status 1.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-10** Optional `--format` may appear in any order relative to `--month` and `--budgets` after the expense CSV path; equivalent flag orderings produce the same stdout and stderr for the same files.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-11** When the expense CSV path cannot be read, the CLI writes exactly one line to stderr equal to the string form of that path, exits with a non-zero code, prints nothing to stdout, and does not print a traceback, regardless of `--format`.
  `[@test] ../tests/test_expenses_cli.py`

## Assumptions

- `--format csv` does not print `month_totals`, `budget_alerts`, or other JSON fields on stdout; when `--budgets` is supplied the CLI still reads and parses the budgets file and applies the same stderr or non-zero exit rules on failure before any CSV success output.
- CSV stderr error lines are emitted in the same order as entries in the JSON `errors` array (file order of recorded errors).
- Duplicate `--format`, `--format` combined with other CLI misuse, and unrecognized tokens after the expense path follow the same usage-message-on-stderr and non-zero exit pattern as other optional-flag errors (including exit code 1 where the CLI already uses `SystemExit(1)` for usage).
- Usage text on stderr may mention `--format` alongside existing optional flags; exact wording is not asserted by tests beyond containing `usage`.
