# Exact decimal money

- **REQ-1** `import_expenses` parses each valid row amount with `decimal.Decimal`, accumulates category, month, and month-and-category totals using `Decimal` addition only (never `float`), and returns total map values as `Decimal` instances.
  `[@test] ../tests/test_expenses_import.py`

- **REQ-2** When two valid expense rows in the same category have amounts `0.10` and `0.20`, `import_expenses` sets that category’s total to exactly `Decimal('0.30')` (not a float such as `0.30000000000000004`).
  `[@test] ../tests/test_expenses_import.py`

- **REQ-3** `parse_budgets_csv` maps each valid budget category to a `Decimal` limit (never `float`) using the same positive-decimal parsing rules as expense amounts.
  `[@test] ../tests/test_expenses_budget_alerts.py`

- **REQ-4** `compute_budget_alerts` reads month-and-category totals and budget limits as `Decimal`, compares them with `Decimal` ordering, and sets each alert’s `total`, `limit`, and `amount_over` to `Decimal` values where `amount_over` equals `total - limit`.
  `[@test] ../tests/test_expenses_budget_alerts.py`

- **REQ-5** When `compute_budget_alerts` is given `month_category_totals` with `Food` total `Decimal('0.30')` for a month and `budgets` with `Food` limit `Decimal('0.10')`, it emits one alert whose `amount_over` is exactly `Decimal('0.20')`.
  `[@test] ../tests/test_expenses_budget_alerts.py`

- **REQ-6** Running `python -m factory_target_py.expenses` with a readable expense CSV prints JSON whose `category_totals` and `month_totals` values are JSON strings, each formatted with exactly two digits after the decimal point (including trailing zeros), for example `"12.30"` rather than `12.3` or a binary float.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** Running `python -m factory_target_py.expenses` with `--budgets` and CSV rows whose valid amounts are `0.10` and `0.20` in the same category prints JSON whose `category_totals` entry for that category is the string `"0.30"`.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-8** When `--budgets` is used and `budget_alerts` is non-empty, each alert object’s `total`, `limit`, and `amount_over` fields in the printed JSON are strings with exactly two decimal places (for example `"120.00"`, `"100.00"`, `"20.00"`).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-9** Without `--top`, CLI usage messages and positional/`--budgets`/`--month` argument rules remain as defined after the month-filter task; when the expense CSV path or (with `--budgets`) the budgets CSV path cannot be read, stderr is exactly one line naming that path with no Python traceback and the exit code is non-zero with no success JSON on stdout; when `--budgets` is used and `parse_budgets_csv` raises `ValueError` after a successful read, stderr still carries the parse error message and the process exits non-zero without success JSON; money JSON string formatting requirements in this spec still apply whenever the CLI prints success JSON.
  `[@test] ../tests/test_expenses_cli.py`

## Assumptions

- Supersedes py-20261004-6bjo REQ-11: totals use `Decimal` exact sums (including the `0.10` + `0.20` case) instead of numeric values compared with float/decimal literal equality.
- Supersedes py-20261004-6bjo assumptions: CLI JSON encodes money map values as two-decimal strings, not JSON numbers.
- Supersedes py-20261004-16e2 REQ-1, REQ-6, and REQ-7: public APIs use `Decimal` for money maps and alert fields instead of `float`.
- Supersedes py-20261004-16e2 REQ-11 and REQ-12: printed JSON money fields use two-decimal strings for totals and budget alert amounts.
- JSON money strings are produced by quantizing each `Decimal` to two fractional digits with `ROUND_HALF_UP` before formatting (so internal sums may retain more precision until serialization).
- Non-money JSON fields (`errors` line numbers and reasons, alert `month` and `category` strings) stay unchanged; only money-bearing keys switch to string encoding in CLI output.
- In-process return values from `import_expenses`, `parse_budgets_csv`, and `compute_budget_alerts` remain Python `Decimal` instances; tests may assert on `Decimal` equality without going through JSON.
- No new runtime dependencies; `decimal.Decimal` from the standard library is the only money type.
