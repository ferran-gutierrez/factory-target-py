# Expense CLI output formats

- **REQ-1** Running `python -m factory_target_py.expenses` with a readable expense CSV and no `--format` flag, or with `--format json`, preserves the existing JSON output, including its category totals, month totals, errors, optional month field, and optional budget alerts; in either case, reading the input file successfully exits with status 0 even when import errors are present.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** Running `python -m factory_target_py.expenses <csv-file> --format csv` with a readable expense CSV prints to stdout only CSV category totals whose first line is exactly `category,total`, followed by one line per selected category as `<category>,<total>`, with totals formatted as the same two-decimal strings used by JSON output.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-3** CSV category-total rows are ordered by category name using plain case-sensitive string comparison, so categories `Banana` and `apple` are emitted in the order `Banana` then `apple` rather than the case-insensitive order; each category is emitted once using its canonical expense category spelling.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** When `--format csv` and `--month YYYY-MM` are supplied, CSV output includes only category totals for valid rows in that month, while invalid rows from the full input are still reported according to REQ-5.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** In CSV format, each invalid expense row is reported to stderr as exactly one line `line <n>: <reason>` using the import error’s line number and reason, no JSON is printed to stdout, and a successfully read input file exits with status 0.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** Any `--format` value other than `json` or `csv`, and `--format` without a following value, prints a usage message to stderr, prints nothing to stdout, and exits with status 1.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** The `--format`, `--month`, and `--budgets` options may be supplied in any order after the expense CSV path; when CSV format is selected together with `--budgets`, stdout still contains only the category-total CSV header and rows, without JSON or budget-alert output.
  `[@test] ../tests/test_expenses_cli.py`

## Assumptions

- Supersedes py-20261004-6bjo REQ-13: the CLI accepts optional `--month` and `--budgets` flags and prints JSON becomes the CLI accepts `--format json` or `--format csv`, defaults to JSON, and prints the selected format while preserving successful-read status 0.
- Supersedes py-20261004-6bjo REQ-14: invalid positional and optional arguments write usage and exit non-zero becomes missing or unsupported `--format` values also write usage, print no stdout, and exit status 1.
- Supersedes py-20261004-16e2 REQ-11: the no-option CLI prints JSON totals and errors becomes the no-option or explicit `--format json` CLI prints the existing JSON totals and errors.
- Supersedes py-20261004-16e2 REQ-12: the budgets CLI prints JSON with budget alerts becomes the no-format or JSON-format budgets CLI preserves its existing JSON and budget-alert output, while CSV format prints category totals only.
- Supersedes py-20261004-16e2 REQ-14: usage errors cover positional count, missing budgets, missing month, and invalid month becomes usage errors additionally cover missing or unsupported format values, with empty stdout and status 1.
- Supersedes py-20261005-mwft REQ-1: a valid month produces a JSON month field becomes a valid month produces that JSON field for default or JSON format; CSV format produces filtered category rows instead.
- Supersedes py-20261005-mwft REQ-5: successful JSON without month matches prior behaviour becomes successful default or explicit JSON output without month matches prior behaviour.
- Category totals in CSV use the same post-import month filtering and canonical category keys as JSON; budget files are still read and validated when `--budgets` is supplied, although successful CSV output omits budget alerts.
- CSV output uses standard newline-separated text with no extra JSON wrapper; an empty selected month still emits the header line only.
- Runtime code uses the Python standard library only and no console-script entry point is added; the command remains available through `python -m factory_target_py.expenses`.
- Unit-style subprocess tests under `tests/` cover CLI behavior; end-to-end tests are out of scope because the contract disables E2E.
