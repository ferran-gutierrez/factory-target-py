# Expense CLI top categories

- **REQ-1** Running `python -m factory_target_py.expenses` with a readable expense CSV and without `--top` prints success JSON that omits the `top_categories` key entirely (the same keys and values as before this task for the same inputs, including optional `--month` and `--budgets`).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** Running `python -m factory_target_py.expenses` with a readable expense CSV and `--top` followed by a valid positive integer `N` prints success JSON that includes `top_categories`, a JSON array of at most `N` objects each with string keys `category` and `total`, where each `category` is a key from the printed `category_totals` object and each `total` is that entry’s two-decimal money string (the same string value as in `category_totals`).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-3** The `top_categories` array is ordered by numeric total descending (using the same `Decimal` amounts behind `category_totals`, not string lexicographic order on the money strings); when two categories share the same total, the object with the lexicographically smaller `category` string (plain ASCII/Unicode string comparison where upper-case letters sort before lower-case) appears first—for example with totals `Travel` `15.00`, `food` `15.00`, and `Food` `10.00`, the first two entries are `{"category": "Travel", "total": "15.00"}` then `{"category": "food", "total": "15.00"}` because `"Travel" < "food"` as strings while `food` and `Travel` tie on amount.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** When `--top N` is supplied together with `--month YYYY-MM`, `top_categories` is built only from the filtered `category_totals` for that month (for example rows `2024-03-01,Food,A,5.00` and `2024-04-01,Travel,B,9.00` with `--month 2024-04 --top 5` yield `top_categories` containing only `Travel`, not `Food`).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** When `N` is greater than the number of categories in the relevant `category_totals` map, `top_categories` lists every category once, still ordered per REQ-3 (for example three categories and `--top 10` yields an array of length three).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** When the relevant `category_totals` map is empty (for example `--month` selects a month with no valid rows), `top_categories` is an empty JSON array `[]`.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** A `--top` value is invalid if it is not a positive integer written only with decimal digits (`0`, a negative sign, a decimal point, or any other non-digit text such as `abc` or `1.5`); for an invalid value the CLI writes a clear error message to stderr (not success JSON), prints nothing to stdout, and exits with status code `1`.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-8** Running `python -m factory_target_py.expenses` with `--top` as the last argument (no value following), with `--top` supplied more than once, or with any other positional or optional-flag misuse covered by prior CLI requirements still writes a usage message to stderr, exits with a non-zero code, and prints no success JSON to stdout; invalid `--top` integer values follow REQ-7 instead of the usage message.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-9** Optional `--top`, `--month`, and `--budgets` flags may appear in any order after the expense CSV path; for example `--top 2 --month 2024-05 --budgets budgets.csv` and `--budgets budgets.csv --month 2024-05 --top 2` produce the same `category_totals`, `top_categories`, and (when budgets are readable) `budget_alerts` for the same files.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-10** When `--top` is supplied with a valid `N` and `--budgets` with a readable budgets CSV, success JSON includes `top_categories` alongside `budget_alerts` without changing budget-alert ordering or matching rules from earlier specs.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-11** When the expense CSV path or (with `--budgets`) the budgets CSV path cannot be read, behaviour is unchanged from prior specs regardless of `--top` (one-line path on stderr, non-zero exit, no traceback, no success JSON); an invalid `--top` value is not checked when the expense file cannot be read first.
  `[@test] ../tests/test_expenses_cli.py`

## Assumptions

- Valid `--top` values are parsed as base-ten positive integers; a value such as `007` is accepted as `N = 7`.
- The stderr line for an invalid `--top` value is exactly `invalid --top value: <token>` where `<token>` is the argument string that followed `--top` (including empty string when `--top` is last, which is handled as usage misuse per REQ-8 rather than REQ-7).
- `top_categories` never includes categories absent from the printed `category_totals` object; it is a ranked slice of that map, not a separate aggregation pass.
- Tie-breaking for equal totals uses Python’s default string ordering on category keys (`<` on `str`), which matches plain string comparison with upper-case before lower-case for ASCII letters.
- Usage strings may mention `[--top N]` alongside existing optional flags; exact usage wording is not part of the contract except that structural misuse still prints a line containing `usage` on stderr.
- Runtime code uses the Python standard library only; no new third-party dependencies.
- End-to-end tests are out of scope (`contract.e2e.applies` is false); behaviour is covered by unit-style subprocess tests under `tests/`.
