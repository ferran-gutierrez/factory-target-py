# Expense CLI output formats

- **REQ-1** Running `python -m factory_target_py.expenses` with a readable expense CSV and no `--format` option, or with `--format json`, prints the same JSON output as the existing expenses CLI and exits with status 0 when the input file was read.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** Running `python -m factory_target_py.expenses` with a readable expense CSV and `--format csv` prints to stdout a CSV document whose first line is `category,total` and whose subsequent lines contain one category total each, with categories ordered by ascending plain string comparison and totals formatted as two-decimal strings.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-3** With `--format csv`, category totals include only valid rows from the selected `--month YYYY-MM` when `--month` is supplied, and include all valid rows when it is not supplied.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** With `--format csv`, categories whose names differ in case sort according to plain string comparison, so an upper-case initial letter precedes a lower-case initial letter even when case-insensitive ordering would produce the opposite order.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** With `--format csv`, every invalid expense row is reported to stderr as one line in the form `line <n>: <reason>` using the importer's line number and reason, no JSON is printed to stdout, and the process exits with status 0 when the input file was read.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** Any format value other than `json` or `csv`, and a `--format` option without a value, prints a usage message to stderr, prints nothing to stdout, and exits with status 1.
  `[@test] ../tests/test_expenses_cli.py`

## Assumptions

- CSV output uses standard CSV serialization for category values when quoting is required; ordinary category names are emitted as `<category>,<total>`.
- `--format` may appear in any order among the existing optional flags, and JSON remains the default when it is omitted.
- In CSV mode, stdout contains only the category-total CSV document; JSON-only fields such as month totals, budget alerts, and the errors array are not serialized there, while CSV validation errors use stderr as specified.
- Supersedes py-20261004-6bjo REQ-13: a readable expense CSV with optional month and budgets flags prints a JSON object becomes the same invocation prints the existing JSON by default or when `--format json`, while `--format csv` prints category totals as CSV.
- Supersedes py-20261004-6bjo REQ-14: usage errors cover missing or invalid month and budgets arguments plus unrecognized optional arguments becomes usage errors also cover missing or invalid format arguments, while json and csv are recognized values.
- Supersedes py-20261004-16e2 REQ-12: a readable budgets invocation prints JSON with budget alerts becomes that invocation prints JSON with budget alerts in the default JSON format, while CSV mode prints only category totals.
- Supersedes py-20261004-16e2 REQ-14: usage errors cover positional, budgets, and month argument failures becomes usage errors also cover missing or invalid format arguments.
- Supersedes py-20261005-mwft REQ-1: month-filtered CLI output is JSON becomes month-filtered CLI output is JSON when the default JSON format is used.
- Supersedes py-20261005-mwft REQ-2: month filtering is specified for printed JSON category totals becomes month filtering applies to JSON category totals and CSV category totals, with CSV output selected explicitly.
- Supersedes py-20261005-mwft REQ-3: month filtering is specified for printed JSON month totals becomes month filtering applies to JSON month totals while CSV output contains category totals only.
- Supersedes py-20261005-mwft REQ-4: an empty selected month is represented in JSON becomes an empty selected month is represented in JSON mode, while CSV mode emits only its header when no category has spending.
- Supersedes py-20261005-mwft REQ-5: successful CLI JSON without month is unchanged becomes successful default-format JSON without month is unchanged, while CSV is an additional explicit output format.
- Supersedes py-20261005-mwft REQ-6: month-filtered budget alerts are printed in JSON becomes month-filtered budget alerts remain in JSON mode, while CSV mode emits only category totals.
- Supersedes py-20261005-mwft REQ-10: all month-filtered import errors are listed in printed JSON becomes all month-filtered import errors remain in JSON mode and are emitted as stderr lines in CSV mode.
- Runtime code remains standard-library-only and the command remains available through `python -m factory_target_py.expenses`.
