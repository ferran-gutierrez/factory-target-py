# Expense CLI output format

- **REQ-1** When `--format` is omitted or `--format json` is supplied, a successful run with a readable expense CSV prints to stdout the same JSON object as before this task for the same expense file and optional `--month` and `--budgets` arguments (including keys, filtered totals, two-decimal money strings, and `errors` content).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** When `--format csv` is supplied and the expense CSV is read successfully, stdout contains only CSV text: the first line is exactly `category,total`, followed by one line per entry in the filtered `category_totals` map (after applying `--month` when that flag is present), ordered by ascending category key using plain string comparison (Unicode code point order, so for example `Banana` sorts before `apple`), each line `<category>,<total>` where `<category>` is the expense canonical category string and `<total>` is the same two-decimal string that would appear under that key in JSON `category_totals` for the same inputs.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-3** When `--format csv` is supplied, each import validation error is written to stderr as exactly one line `line <n>: <reason>` where `<n>` and `<reason>` match the `line` and `reason` fields of the corresponding object in the JSON `errors` array that `--format json` would produce for the same file, in the same order as those objects; stdout must not contain JSON.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** When the expense CSV path was read successfully, both default or explicit `--format json` and `--format csv` exit with status code 0 even when the file contains invalid data rows (errors appear in JSON or on stderr per format).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** When `--format` is present without a following value, or the value is neither `json` nor `csv`, the CLI writes a usage message to stderr, prints nothing to stdout, and exits with status code 1.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** Optional `--format` may appear together with `--month` and/or `--budgets` in any order after the expense CSV path; `--format csv` with `--month YYYY-MM` limits CSV rows to the same filtered `category_totals` as JSON output for that month.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** Tests cover `--format csv` with an expense file that includes invalid rows (asserting stderr `line <n>: <reason>` lines and CSV stdout) and with at least two distinct canonical categories whose names order differently under case-insensitive comparison than under plain string comparison (for example categories `Banana` and `apple`, where ASCII order lists `Banana` before `apple` but case-insensitive order lists `apple` first).
  `[@test] ../tests/test_expenses_cli.py`

- When `--format csv` and `--budgets` are both supplied and budgets processing fails (unreadable path or `ValueError` from parse), behaviour matches prior CLI failure semantics (stderr message, non-zero exit, no stdout success output); when budgets succeed, stdout is still CSV category totals only.
- Runtime code uses the Python standard library only; no new third-party dependencies.
- `pyproject.toml` cannot gain console script entry points; the CLI remains `python -m factory_target_py.expenses`.
