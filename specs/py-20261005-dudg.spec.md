# Expense CLI output format

- **REQ-1** Running `python -m factory_target_py.expenses` with a readable expense CSV uses JSON output by default, and `--format json` produces the same JSON output and exit status as the default invocation, including all existing fields and two-decimal money strings.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** When `--format csv` is supplied with a readable expense CSV, stdout contains only a CSV header `category,total` followed by one row for each category total, with categories ordered by plain ascending string comparison and totals formatted as the same two-decimal strings used in JSON output.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-3** When `--format csv` is combined with `--month YYYY-MM`, CSV category totals include only valid expense rows in the selected month and use the same month filtering as JSON output.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** When `--format csv` processes a readable expense CSV containing invalid rows, stderr contains one line `line <n>: <reason>` for each JSON error in the same order, stdout contains no JSON or error output, and the process exits with status 0.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** In both JSON and CSV formats, a readable expense file results in exit status 0 regardless of whether import validation errors were found.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** A `--format` option with no following value, or with a value other than `json` or `csv`, writes a usage message to stderr, writes nothing to stdout, and exits with status 1; omitting `--format` remains valid and selects JSON.
  `[@test] ../tests/test_expenses_cli.py`

## Assumptions

- The `--format` option follows the existing order-independent optional-flag convention and may appear with `--month` and `--budgets` in any supported order.
- CSV output excludes month totals, budget alerts, and JSON error objects from stdout; CSV validation errors are emitted only on stderr.
- Format values are matched exactly as lowercase `json` or `csv`; no aliases or case-insensitive values are accepted.
- Existing JSON behavior, including the optional `month` field and budget-alert output, is unchanged when the format is omitted or explicitly set to `json`.
