# Expense CLI top categories

- **REQ-1** Running `python -m factory_target_py.expenses` with a readable expense CSV and `--top` followed by a positive integer `N` written only with decimal digits (for example `--top 2`) prints success JSON that includes a `top_categories` key whose value is a JSON array of at most `N` objects, each with string keys `category` and `total` where `total` is a two-decimal money string.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** Each `top_categories` entry’s `category` and `total` match one category from the printed `category_totals` object (same canonical category spelling and the same two-decimal total string); when `--month YYYY-MM` is also supplied, `top_categories` is built from the filtered `category_totals` for that month, not from unfiltered import totals—for example rows `2024-03-01,Food,A,5.00` and `2024-04-01,Food,B,9.00` with `--month 2024-04 --top 1` yield `"category_totals": {"Food": "9.00"}` and `"top_categories": [{"category": "Food", "total": "9.00"}]`.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-3** `top_categories` is ordered by descending `total` (compared as decimal amounts); when two categories share the same total, the entry with the lexicographically smaller `category` string (plain string comparison where upper-case letters sort before lower-case) appears first—for example `category_totals` `{"Travel": "15.00", "food": "15.00", "Rent": "20.00"}` with `--top 3` yields `top_categories` category order `["Rent", "Travel", "food"]` because `20.00` is highest and `"Travel"` precedes `"food"` under ASCII order at equal `15.00`.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** When `--top N` is supplied and `N` is greater than the number of categories in the printed `category_totals`, `top_categories` lists every category once, still ordered per REQ-3—for example three categories and `--top 10` yields a three-element array.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** When `--top N` is supplied and the printed `category_totals` object is empty (for example `--month 2024-12` with no valid rows in that month), `top_categories` is an empty JSON array and the process still exits 0 on success.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** When `--top` is not supplied, successful CLI JSON omits the `top_categories` key entirely and every other key and value matches the behaviour immediately before this task for the same expense CSV and the same optional `--month` and `--budgets` inputs.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** When `--top` is followed by a value that is not a positive integer written only with decimal digits— including `0`, a negative numeral such as `-3`, a value containing a decimal point such as `2.5`, or non-numeric text such as `two`—the CLI writes a clear error message to stderr, prints nothing to stdout, and exits with status code 1.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-8** Running `python -m factory_target_py.expenses` with `--top` as the last argument (no value following) writes a usage message to stderr and exits with a non-zero code without printing success JSON to stdout.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-9** Optional `--top`, `--month`, and `--budgets` flags may appear in any order after the expense CSV path; for example `expenses.csv --top 2 --month 2024-05 --budgets budgets.csv` and `expenses.csv --budgets budgets.csv --month 2024-05 --top 2` produce the same `category_totals`, `top_categories`, and (when `--budgets` is present) `budget_alerts` for the same files.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-10** When `--top N` is supplied together with `--budgets`, unreadable expense or budgets paths, invalid budgets CSV content after a successful read, and invalid `--month` values still follow the same stderr and exit-code rules as before this task; a valid `--top` does not bypass those failures.
  `[@test] ../tests/test_expenses_cli.py`

- Invalid `--top` stderr text is a single human-readable line that identifies the `--top` value as invalid; exact wording is not fixed beyond being non-empty and not a Python traceback.
- A `--top` value matches “positive integer written in decimal digits” only when it is non-empty, consists solely of characters `0`–`9`, has no sign or decimal point, and parses to an integer greater than zero (so `007` is accepted as 7).
- Supplying the same optional flag twice (for example two `--top` options) is treated as CLI misuse and produces a usage message on stderr with a non-zero exit, consistent with duplicate `--month` or `--budgets`.
- `top_categories` lists each category at most once even if `category_totals` construction rules change in the future; totals are taken from the final printed `category_totals` map.
- `pyproject.toml` cannot gain console script entry points; the CLI remains `python -m factory_target_py.expenses`.
- Runtime code uses the Python standard library only; no new third-party dependencies.
