# Expense CLI top categories

- **REQ-1** Running `python -m factory_target_py.expenses` with a readable expense CSV and `--top` followed by a positive integer written only in decimal digits (for example `--top 3`) prints success JSON that includes a `top_categories` key whose value is a JSON array.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** Each object in `top_categories` has exactly the keys `category` (the expense canonical category string) and `total` (a two-decimal money string); for every entry, `total` equals the `category_totals` value for that same `category` key in the same printed JSON object.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-3** `top_categories` is built from the same category totals map shown in `category_totals` (after any `--month YYYY-MM` filtering applied to that map); for example, with rows in `Food` only in `2024-04` and `2024-05`, `--month 2024-04 --top 5` lists only categories with spending in `2024-04`, matching the filtered `category_totals`.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** `top_categories` is ordered by descending numeric total (compare underlying money amounts, not lexicographic string order); when two categories share the same total, they are ordered by ascending `category` using plain Python string comparison (`<` on the category strings), so for equal totals `Apple` sorts before `apple` and `Food` before `Travel`.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** The array length is at most `N`; when the number of categories is less than `N`, every category appears once; when there are no categories in the totals map, `top_categories` is an empty array.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** When `--top` is followed by `0`, a negative integer, a token containing a decimal point, a token that is not entirely decimal digits, or any other non-positive-integer text, the CLI writes the single line `invalid --top value` to stderr, prints nothing to stdout, and exits with status `1`.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** When `--top` is not supplied, successful CLI JSON omits the `top_categories` key and otherwise matches the same keys and values as before this task for the same expense CSV and optional `--month` and `--budgets` inputs.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-8** Running with `--top` as the last argument (no value following), a second `--top` flag, or an unrecognized optional token after the expense CSV path writes the CLI usage message to stderr and exits with a non-zero code, consistent with other optional-flag misuse.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-9** Optional `--top`, `--month`, and `--budgets` flags may appear in any order after the expense CSV path; the same files and flags in different orders produce the same `category_totals`, `top_categories`, and (when present) `budget_alerts` for the same data.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-10** When the expense CSV path or (with `--budgets`) the budgets CSV path cannot be read, or `parse_budgets_csv` raises `ValueError` after a successful budgets read, CLI stderr and exit behaviour remain as defined in prior expense CLI specs regardless of whether `--top` is present; invalid `--top` values still follow REQ-6 before success JSON is printed.
  `[@test] ../tests/test_expenses_cli.py`

## Assumptions

- Supersedes py-20261004-6bjo REQ-13: one expense CSV path with optional --month and --budgets flags becomes one expense CSV path with optional --month, --top N, and --budgets flags, with month filtering and JSON per later CLI requirements
- Supersedes py-20261004-6bjo REQ-14: usage error on missing --month value or invalid --month becomes usage error also on --top without a following value (invalid --top numeric values use REQ-6 instead of the usage line)
- Supersedes py-20261004-16e2 REQ-14: usage error on --month without value or invalid --month becomes usage error also on --top without a following value; invalid --top numeric values are not usage errors
- Supersedes py-20261005-mwft REQ-5: unchanged JSON when --month is not supplied becomes unchanged JSON when neither --month nor --top is supplied (no top_categories key)
- Supersedes py-20261005-kj6f REQ-9: without --month CLI usage and file-error rules unchanged becomes without --month or --top those rules unchanged; invalid --top N writes invalid --top value on stderr; success JSON without --top omits top_categories
- Positive `--top` values are parsed with `int()` on the argv token (so leading zeros such as `01` are accepted as `1`); only the decimal-digit form without sign or radix point is allowed for success paths
- `top_categories` is included in success JSON whenever `--top` is valid, alongside existing keys (`category_totals`, `month_totals`, `errors`, optional `month`, optional `budget_alerts`); key order in the serialized JSON object is not specified
- Runtime code uses the Python standard library only; no new third-party dependencies
- `pyproject.toml` cannot gain console script entry points; the CLI remains `python -m factory_target_py.expenses`
