# Expense CLI output format

- **REQ-1** Running `python -m factory_target_py.expenses` with a readable expense CSV path and no `--format` flag produces the same stdout, stderr, and exit code as immediately before this task for the same `--month` and `--budgets` arguments (JSON success object on stdout when the expense file is read and no budgets parse failure occurs).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** Running with `--format json` produces the same stdout, stderr, and exit code as omitting `--format` for the same expense path and other flags.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-3** Running with `--format csv` and a readable expense CSV prints to stdout only CSV text: the first line is exactly `category,total`, followed by one line per category present in the filtered `category_totals` map as `<category>,<total>` where `<total>` is the same two-decimal string that JSON format would use for that category key; lines after the header are ordered by ascending category name using plain string comparison (Unicode code point / byte order as Python `<` on `str`, so an uppercase letter sorts before a lowercase letter in the same position).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** When `--format csv` and `--month YYYY-MM` are both supplied, the CSV body lists only categories and totals for that month (the same filtered `category_totals` map JSON format would emit under `--month`).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** When `--format csv` and the import yields one or more validation errors, the process prints no JSON to stdout; each error is written to stderr as exactly one line `line <n>: <reason>` where `<n>` and `<reason>` match the `line` and `reason` fields of the corresponding object in the JSON `errors` array for the same input file.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** When `--format csv` and the expense CSV file was read successfully, the exit code is `0` even when stderr contains one or more `line <n>: <reason>` lines for invalid rows.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** When `--format csv` is used with an expense CSV that includes at least two valid categories whose names sort differently under plain string comparison than under case-insensitive comparison (for example canonical categories `apple` and `Banana` with both present in totals), the CSV data lines after the header appear in plain string ascending order (for that example `Banana,<total>` before `apple,<total>`).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-8** A `--format` value is invalid if the flag is present without a following token, or the following token is not exactly `json` or `csv`; in those cases the CLI writes a usage message to stderr, prints nothing to stdout, and exits with status `1`.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-9** Optional `--format`, `--month`, and `--budgets` flags may appear in any order after the expense CSV path; for example `--format csv --month 2024-04` and `--month 2024-04 --format csv` produce the same CSV stdout for the same files.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-10** When the expense CSV path cannot be read, the CLI still writes exactly one stderr line naming that path, exits non-zero, and prints no successful format output on stdout, regardless of `--format`.
  `[@test] ../tests/test_expenses_cli.py`
