# Top categories CLI summary

- **REQ-1** The package exposes `compute_top_categories(category_totals: dict[str, decimal.Decimal], n: int) -> list[dict]` in `factory_target_py.expenses` that returns at most `n` dicts, each with string keys `category` and `total` (`decimal.Decimal`), chosen from `category_totals` and ordered by descending `total`, then by ascending `category` using case-insensitive comparison on the category name when two totals are equal.
  `[@test] ../tests/test_expenses_top_categories.py`

- **REQ-2** For `category_totals` `{"Travel": Decimal('50.00'), "Food": Decimal('100.00'), "Rent": Decimal('75.00')}` and `n=2`, `compute_top_categories` returns a list whose `category` values are `["Food", "Rent"]` with matching `total` values `Decimal('100.00')` and `Decimal('75.00')` (not including `Travel`, which ranks third).
  `[@test] ../tests/test_expenses_top_categories.py`

- **REQ-3** When `category_totals` maps `apple` and `Banana` each to `Decimal('10.00')` and `n=2`, `compute_top_categories` lists the `apple` entry before the `Banana` entry because `apple` precedes `Banana` under case-insensitive category comparison even though uppercase `B` sorts before lowercase `a` in ASCII lexicographic order.
  `[@test] ../tests/test_expenses_top_categories.py`

- **REQ-4** When `n` is greater than the number of keys in `category_totals`, `compute_top_categories` returns every category in the same descending-total then ascending-category order as when `n` equals that key count (for example three categories and `n=10` yields three entries, not an error).
  `[@test] ../tests/test_expenses_top_categories.py`

- **REQ-5** When `category_totals` is empty, `compute_top_categories` returns an empty list for any positive `n`.
  `[@test] ../tests/test_expenses_top_categories.py`

- **REQ-6** Running `python -m factory_target_py.expenses` with a readable expense CSV and `--top` followed by a positive integer `N` prints success JSON that includes `top_categories`, a JSON array of objects each with string keys `category` and `total`, where `total` is formatted with exactly two digits after the decimal point and the array matches `compute_top_categories` applied to the same `category_totals` map printed in the payload (after `--month` filtering when that flag is present).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** Running `python -m factory_target_py.expenses` with a readable expense CSV and no `--top` flag prints success JSON whose top-level keys are unchanged from the behaviour before this task for the same other flags (no `top_categories` key).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-8** Running `python -m factory_target_py.expenses` with `--top` followed by `0`, a negative integer (for example `-1`), or a value that is not a base-10 integer string (for example `abc` or `1.5`) writes a clear error message to stderr that identifies the `--top` value as invalid, exits with a non-zero code, and prints no success JSON to stdout.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-9** Running `python -m factory_target_py.expenses` with `--top` as the last argument (no value following) or with a duplicate `--top` flag writes a usage message to stderr and exits with a non-zero code.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-10** When `--month YYYY-MM` and `--top N` are both supplied, `top_categories` ranks categories using the filtered `category_totals` for that month only; for example rows `2024-03-01,Food,A,5.00` and `2024-04-01,Travel,B,50.00` with `--month 2024-04 --top 1` yield `"top_categories": [{"category": "Travel", "total": "50.00"}]` and no `Food` entry.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-11** Optional `--top`, `--month`, and `--budgets` flags may appear in any order after the expense CSV path; the same `N` and files produce the same `top_categories` regardless of flag order among those options.
  `[@test] ../tests/test_expenses_cli.py`

## Assumptions

- `compute_top_categories` assumes `n` is a positive integer; callers (the CLI after validation) pass only valid `n`; invalid CLI values are rejected before calling the function.
- Invalid `--top` error text is a single stderr line without a Python traceback; wording is implementation-defined provided it clearly states that the `--top` argument must be a positive integer.
- Positive integer parsing accepts optional leading zeros in the argument string (for example `--top 02` means `N=2`).
- Category names in `top_categories` use expense canonical spellings from `category_totals` keys (consistent with case-insensitive merging elsewhere).
- `pyproject.toml` cannot gain console script entry points; the CLI remains `python -m factory_target_py.expenses`.
- Runtime code uses the Python standard library only; no new third-party dependencies.
