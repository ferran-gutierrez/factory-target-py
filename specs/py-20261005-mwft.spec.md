# Expense CLI month filter

- **REQ-1** Running `python -m factory_target_py.expenses` with a readable expense CSV and `--month` followed by a valid `YYYY-MM` string prints JSON that includes `"month"` set to that same `YYYY-MM` string, and omits `"month"` when `--month` is not supplied.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** When `--month YYYY-MM` is supplied, `category_totals` in the printed JSON sums only valid expense rows whose date falls in that calendar month; for example, given rows dated `2024-03-15` and `2024-04-01` both in category `Food` with amounts `5.00` and `7.00`, `--month 2024-04` yields `"category_totals": {"Food": "7.00"}` (not `"12.00"`).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-3** When `--month YYYY-MM` is supplied, `month_totals` in the printed JSON includes only the requested month key when that month has spending, with the filtered sum as a two-decimal string; for the same example as REQ-2, `--month 2024-04` yields `"month_totals": {"2024-04": "7.00"}` with no `2024-03` entry.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** When `--month YYYY-MM` is supplied and no valid expense row falls in that month, the printed JSON has empty `category_totals` and `month_totals` objects, `"month"` set to the requested value, exit code 0, and (when `--budgets` is also supplied) an empty `budget_alerts` array.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** When `--month` is not supplied, successful CLI JSON keys and values match the behaviour before this task (including no top-level `"month"` key) for the same expense and optional `--budgets` inputs.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** When both `--month YYYY-MM` and `--budgets` with a readable budgets CSV are supplied, `budget_alerts` is computed only from spending in that month; for example, with `Food` totals `8.00` in `2024-05` and `20.00` in `2024-06`, budget limit `Food` `10.00`, and `--month 2024-05`, the alert list contains only the `2024-05` `Food` alert and not a `2024-06` alert.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** A `--month` value is invalid if it is not exactly seven characters matching `YYYY-MM`, the month part is not `01` through `12`, or the year-month does not denote a valid Gregorian month; in those cases the CLI writes a usage message to stderr, exits with a non-zero code, and prints no success JSON to stdout.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-8** Running `python -m factory_target_py.expenses` with `--month` as the last argument (no value following) writes a usage message to stderr and exits with a non-zero code.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-9** Optional `--month` and `--budgets` flags may appear in any order after the expense CSV path; for example `--month 2024-05 --budgets budgets.csv` and `--budgets budgets.csv --month 2024-05` produce the same filtered totals and alerts for the same files.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-10** When `--month` is supplied, the `errors` array in printed JSON still lists every import validation error from the full expense CSV (not restricted to rows in the selected month).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-11** Unreadable expense files, unreadable budgets files when `--budgets` is used, and invalid budgets CSV content still produce the same stderr and exit-code behaviour as before this task, regardless of whether `--month` is present.
  `[@test] ../tests/test_expenses_cli.py`

## Assumptions

- Supersedes py-20261004-6bjo REQ-13: CLI accepts one expense CSV path plus optional `--month` and `--budgets` flags instead of exactly one argument only.
- Supersedes py-20261004-6bjo REQ-14: usage errors also cover missing/invalid `--month` and malformed optional-flag combinations instead of only zero or excess positional arguments.
- Supersedes py-20261004-16e2 REQ-12: with `--budgets`, alerts use month-filtered `month_category_totals` when `--month` is present instead of always using the full import totals.
- Supersedes py-20261004-16e2 REQ-14: usage errors also cover `--month` without a value and invalid `--month` values instead of only positional and `--budgets` path errors.
- Supersedes py-20261005-kj6f REQ-9: unchanged CLI behaviour is defined relative to the pre-month-filter command line (without `--month`); new month validation and filtered JSON fields are excluded from that stability requirement.
- Month filtering applies after a full `import_expenses` pass; only aggregation in CLI output and alert computation is restricted, not CSV parsing or per-line validation.
- Calendar month membership uses the expense row date’s `YYYY-MM` prefix, consistent with existing month aggregation keys.
- Invalid `--month` values are reported via the same usage message pattern as other CLI misuse (no separate error reason string).
- Optional flags are parsed with order-independent semantics (equivalent to `argparse` optional arguments).
- `pyproject.toml` cannot gain console script entry points; the CLI remains `python -m factory_target_py.expenses`.
- Runtime code uses the Python standard library only; no new third-party dependencies.
