# Expense CLI month filter

- **REQ-1** When `--format` is omitted or `--format json`, running `python -m factory_target_py.expenses` with a readable expense CSV and `--month` followed by a valid `YYYY-MM` string prints JSON that includes `"month"` set to that same `YYYY-MM` string, and omits `"month"` when `--month` is not supplied.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** When `--month YYYY-MM` is supplied, filtered `category_totals` sum only valid expense rows whose date falls in that calendar month; for example, given rows dated `2024-03-15` and `2024-04-01` both in category `Food` with amounts `5.00` and `7.00`, `--month 2024-04` yields JSON `"category_totals": {"Food": "7.00"}` (not `"12.00"`) when `--format` is omitted or `json`, and the same single `Food,7.00` CSV data line when `--format csv`.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-3** When `--month YYYY-MM` is supplied and `--format` is omitted or `--format json`, `month_totals` in the printed JSON includes only the requested month key when that month has spending, with the filtered sum as a two-decimal string; for the same example as REQ-2, `--month 2024-04` yields `"month_totals": {"2024-04": "7.00"}` with no `2024-03` entry.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** When `--month YYYY-MM` is supplied and no valid expense row falls in that month, and `--format` is omitted or `--format json`, the printed JSON has empty `category_totals` and `month_totals` objects, `"month"` set to the requested value, exit code 0, and (when `--budgets` is also supplied) an empty `budget_alerts` array; when `--format csv`, stdout is only the header line `category,total` with exit code 0.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** When `--month` is not supplied and `--format` is omitted or `--format json`, successful CLI JSON keys and values match the behaviour before this task (including no top-level `"month"` key) for the same expense and optional `--budgets` inputs.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** When both `--month YYYY-MM` and `--budgets` with a readable budgets CSV are supplied and `--format` is omitted or `--format json`, `budget_alerts` is computed only from spending in that month; for example, with `Food` totals `8.00` in `2024-05` and `20.00` in `2024-06`, budget limit `Food` `10.00`, and `--month 2024-05`, the alert list contains only the `2024-05` `Food` alert and not a `2024-06` alert.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** A `--month` value is invalid if it is not exactly seven characters matching `YYYY-MM`, the month part is not `01` through `12`, or the year-month does not denote a valid Gregorian month; in those cases the CLI writes a usage message to stderr, exits with a non-zero code, and prints no success JSON or CSV category totals to stdout.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-8** Running `python -m factory_target_py.expenses` with `--month` as the last argument (no value following) writes a usage message to stderr, exits with a non-zero code, and prints no success JSON or CSV category totals to stdout.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-9** Optional `--month`, `--budgets`, and `--format` flags may appear in any order after the expense CSV path; for example `--month 2024-05 --budgets budgets.csv` and `--budgets budgets.csv --month 2024-05` produce the same filtered totals and alerts for the same files when `--format` is omitted or `json`, and the same CSV category totals when `--format csv`.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-10** When `--month` is supplied, import validation errors still reflect the full expense CSV (not restricted to rows in the selected month); with `--format` omitted or `--format json`, the `errors` array in printed JSON lists every such error, and with `--format csv` each error appears as one stderr line `line <n>: <reason>` and not in stdout.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-11** When the expense CSV path or (with `--budgets`) the budgets CSV path cannot be read, the CLI writes exactly one line to stderr equal to the string form of the unreadable path, exits with a non-zero code, does not print a Python traceback, and prints no success JSON or CSV category totals, regardless of whether `--month` or `--format` is present; when `--budgets` is used and the budgets file is readable but `parse_budgets_csv` raises `ValueError`, stderr still carries the parse error message and the process exits non-zero without success JSON or CSV category totals.
  `[@test] ../tests/test_expenses_cli.py`

## Assumptions

- Supersedes py-20261004-6bjo REQ-13: exactly one CSV path argument prints category_totals, month_totals, and errors JSON becomes one expense CSV path with optional --month and --budgets flags, month filtering when requested, and JSON per later CLI requirements
- Supersedes py-20261004-6bjo REQ-14: usage error on zero or more than one CLI argument becomes usage error on bad positional count plus missing, invalid, or unrecognized optional flags including --month and --budgets
- Supersedes py-20261004-16e2 REQ-12: --budgets computes budget_alerts from full month_category_totals becomes --budgets computes budget_alerts from month-filtered totals when --month is set and includes a month JSON field when --month is set
- Supersedes py-20261004-16e2 REQ-14: usage error on bad positional count or --budgets without path becomes usage error also on --month without value or invalid --month value
- Supersedes py-20261005-kj6f REQ-9: all CLI usage and file-error exit behaviour unchanged from pre-decimal task becomes without --month, positional and --budgets usage and file-error exits unchanged while --month adds its own validation and JSON fields
- Month filtering applies after a full `import_expenses` pass; only aggregation in CLI output and alert computation is restricted, not CSV parsing or per-line validation.
- Calendar month membership uses the expense row date’s `YYYY-MM` prefix, consistent with existing month aggregation keys.
- Invalid `--month` values are reported via the same usage message pattern as other CLI misuse (no separate error reason string).
- Optional flags are parsed with order-independent semantics (equivalent to `argparse` optional arguments).
- `pyproject.toml` cannot gain console script entry points; the CLI remains `python -m factory_target_py.expenses`.
- Runtime code uses the Python standard library only; no new third-party dependencies.
