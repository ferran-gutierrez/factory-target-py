# Expense CLI output format

- **REQ-1** Running `python -m factory_target_py.expenses` with a readable expense CSV path and no `--format` flag prints to stdout the same JSON object as before this task (including default `--format json` behaviour for keys, money string encoding, optional `--month` and `--budgets` fields, and full-file `errors` in JSON when format is JSON).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** Running with `--format json` and a readable expense CSV prints to stdout JSON byte-for-byte equivalent to omitting `--format` for the same expense file and the same optional `--month` and `--budgets` arguments.
  `[@test] ../tests/test_expenses_cli_format.py`

- **REQ-3** Running with `--format csv` and a readable expense CSV prints to stdout only CSV text: the first line is exactly `category,total`, followed by one line per category in `category_totals` after any `--month` filtering, ordered by ascending category name using plain string comparison (Unicode code point order, so an upper-case letter sorts before a lower-case letter in the same position), each line `<category>,<total>` where `<category>` is the expense canonical category key and `<total>` is the same two-decimal money string that would appear for that key in JSON `category_totals`, with no other stdout lines.
  `[@test] ../tests/test_expenses_cli_format.py`

- **REQ-4** When `--format csv` and `--month YYYY-MM` are both supplied, the CSV rows reflect `category_totals` restricted to valid expense rows in that month (the same filtered map as JSON output for those flags), not whole-file category totals.
  `[@test] ../tests/test_expenses_cli_format.py`

- **REQ-5** When `--format csv` is used with a readable expense CSV that contains invalid data rows, the process exits with code 0, prints no JSON to stdout, prints the CSV header and valid category total lines as in REQ-3, and writes each import validation error to stderr as exactly one line `line <n>: <reason>` where `<n>` and `<reason>` match the `line` and `reason` fields of the corresponding entry in the JSON `errors` array that `--format json` would emit for the same file.
  `[@test] ../tests/test_expenses_cli_format.py`

- **REQ-6** When `--format csv` is used with a readable expense CSV whose canonical categories include two names that sort differently under case-insensitive comparison than under plain string comparison (for example `Banana` and `apple`), the CSV data lines after the header appear in plain string ascending order (for that pair, `Banana,<total>` before `apple,<total>`), not case-insensitive order.
  `[@test] ../tests/test_expenses_cli_format.py`

- **REQ-7** When `--format` is supplied with a value other than `json` or `csv`, or when `--format` is the last token with no following value, the CLI writes a usage message to stderr, prints nothing to stdout, and exits with status code 1 without reading the expense CSV.
  `[@test] ../tests/test_expenses_cli_format.py`

- **REQ-8** When the expense CSV path is readable, both `--format json` (or omitted) and `--format csv` exit with status code 0 even when the file contains invalid rows that produce import errors; unreadable expense paths, unreadable budgets paths when `--budgets` is used, invalid budgets CSV after a successful read, and CLI misuse still follow prior stderr and exit-code rules and produce no success stdout output for either format.
  `[@test] ../tests/test_expenses_cli_format.py`

- **REQ-9** Optional `--format`, `--month`, and `--budgets` flags may appear in any order after the expense CSV path; for example `--format csv --month 2024-04` and `--month 2024-04 --format csv` produce the same stdout and stderr for the same files.
  `[@test] ../tests/test_expenses_cli_format.py`

- `--format` accepts exactly `json` and `csv`; comparison is case-sensitive (`JSON` is invalid).
- When `--budgets` is supplied with `--format csv`, budgets are still read and validated and budget alerts are still computed for side effects on exit codes, but no budget alert data is written to stdout in CSV mode.
- CSV output uses Unix line endings (`\n`) and no trailing newline requirement beyond what `print` emits for the last line.
- Duplicate optional flags (`--format`, `--month`, or `--budgets` twice) still produce a usage message and exit 1, consistent with existing CLI parsing.
- Runtime code uses the Python standard library only; no new third-party dependencies.
- `pyproject.toml` cannot gain console script entry points; the CLI remains `python -m factory_target_py.expenses`.
