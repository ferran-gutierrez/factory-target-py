# Expense CLI top categories

- **REQ-1** Running `python -m factory_target_py.expenses` with a readable expense CSV and without `--top` prints success JSON whose keys and values match the behaviour before this task for the same expense file and the same optional `--month` and/or `--budgets` arguments (including omission of `top_categories`).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** Running `python -m factory_target_py.expenses` with a readable expense CSV and `--top` followed by a positive integer `N` prints success JSON that includes `top_categories`, a JSON array of objects each with string keys `category` and `total`, where `total` is formatted with exactly two digits after the decimal point as a JSON string (consistent with `category_totals` money encoding).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-3** Each `top_categories` entry’s `category` is an expense canonical category string and its `total` equals the corresponding value in the printed JSON `category_totals` map for the same CLI run (after any `--month` filtering applied to `category_totals`).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** `top_categories` lists at most `N` entries, chosen from categories with the highest totals in `category_totals` for that run, ordered by descending `total` and, when two categories share the same total, by ascending `category` using lexicographic string comparison on the canonical category names; for example with `--top 3` and `category_totals` equivalent to `Travel` `10.00`, `Food` `10.00`, and `Apple` `5.00`, the `category` values in order are `["Food", "Travel", "Apple"]` (not `["Travel", "Food", "Apple"]`).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** When `N` is greater than the number of categories present in `category_totals`, `top_categories` includes every such category and no others, still ordered by descending total then ascending category name.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** When `--top` is followed by `0`, a negative integer, or a token that is not a positive integer (for example `abc` or `1.5`), the CLI writes a clear error message to stderr that indicates `--top` requires a positive integer, exits with a non-zero code, and prints no success JSON to stdout.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** Running `python -m factory_target_py.expenses` with `--top` as the last argument (no value following) writes a usage message to stderr and exits with a non-zero code.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-8** Optional `--top`, `--month`, and `--budgets` flags may appear in any order after the expense CSV path; for example `--top 2 --month 2024-04` and `--month 2024-04 --top 2` yield the same `category_totals` and `top_categories` for the same files.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-9** When `--month YYYY-MM` is supplied together with `--top N`, `top_categories` is computed from the same month-filtered `category_totals` printed in JSON (not from full-file totals); for rows with `Food` `5.00` in `2024-03` and `Food` `7.00` in `2024-04`, `--month 2024-04 --top 1` yields one `top_categories` entry with `category` `Food` and `total` `"7.00"`.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-10** When the expense CSV path or (with `--budgets`) the budgets CSV path cannot be read, or when `--budgets` is used and `parse_budgets_csv` raises `ValueError` after a successful read, stderr and exit behaviour remain as defined in prior expense CLI requirements regardless of whether `--top` is present; invalid `--top` values are rejected before reading files when `--top` appears with its value in the argument list.
  `[@test] ../tests/test_expenses_cli.py`
