# Expense CLI top categories

- **REQ-1** The package exposes `compute_top_categories(category_totals: dict[str, decimal.Decimal], n: int) -> list[dict]` in `factory_target_py.expenses` that returns at most `n` entries, each a dict with string key `category` and `decimal.Decimal` key `total`, drawn from `category_totals` and ordered by descending `total` and then ascending `category` using lexicographic string comparison on each category name; for `category_totals` `{"Travel": Decimal('50.00'), "Food": Decimal('30.00'), "Rent": Decimal('50.00')}` and `n` `2`, the returned list’s `category` values are `["Rent", "Travel"]` (both totals `50.00`, and `"Rent"` precedes `"Travel"` lexicographically).
  `[@test] ../tests/test_expenses_top_categories.py`

- **REQ-2** When `n` is greater than or equal to the number of keys in `category_totals`, `compute_top_categories` returns one entry for every category in `category_totals`, still ordered by descending total then ascending category name; for three distinct categories and `n` `10`, the list length is `3`.
  `[@test] ../tests/test_expenses_top_categories.py`

- **REQ-3** When `category_totals` is empty, `compute_top_categories` returns an empty list for any positive `n`.
  `[@test] ../tests/test_expenses_top_categories.py`

- **REQ-4** Running `python -m factory_target_py.expenses` with a readable expense CSV and `--top` followed by a positive integer `N` prints success JSON that includes `top_categories`, a JSON array of objects each with string keys `category` and `total`, where `total` is a two-decimal money string, the array length is `min(N, number of categories in the printed category_totals)`, and the array order matches `compute_top_categories` applied to the same category totals map used for the printed `category_totals` object (after any `--month` filtering).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** Running `python -m factory_target_py.expenses` with a readable expense CSV and no `--top` flag prints success JSON with the same keys and values as before this task for the same expense file and any combination of `--month` and/or `--budgets` flags (no `top_categories` key).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** Running `python -m factory_target_py.expenses` with `--top` followed by `0`, a negative integer (for example `-1`), or a value that is not a base-ten positive integer (for example `abc` or `1.5`) writes a clear error message to stderr, exits with a non-zero code, and prints no success JSON to stdout.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** Running `python -m factory_target_py.expenses` with `--top` as the last argument (no value following), with a duplicate `--top` flag, or with `--top` immediately followed by another flag token such as `--month` or `--budgets`, writes a usage message to stderr and exits with a non-zero code.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-8** Optional `--top`, `--month`, and `--budgets` flags may appear in any order after the expense CSV path; for example `--top 2 --month 2024-05 --budgets budgets.csv` and `--budgets budgets.csv --month 2024-05 --top 2` produce the same `category_totals`, `top_categories`, and (when `--budgets` is present) `budget_alerts` for the same files.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-9** When `--month YYYY-MM` and `--top N` are both supplied, `top_categories` ranks only categories and totals from spending in that month (consistent with filtered `category_totals`); unreadable expense or budgets paths, invalid `--month`, invalid budgets CSV content, and invalid `--top` values still follow the same stderr and exit-code rules as before this task regardless of which other flags are present.
  `[@test] ../tests/test_expenses_cli.py`

## Assumptions

- `compute_top_categories` assumes `n` is a positive integer; callers (the CLI) validate `N` before calling.
- Tie-breaking by ascending category name uses lexicographic comparison on the expense canonical category strings stored in `category_totals` (case-sensitive), not case-insensitive ordering.
- Invalid `--top` values (zero, negative, or non-integer) share one stderr message pattern such as `invalid --top value: must be a positive integer` rather than the generic usage line; missing `--top` value, duplicate `--top`, or `--top` not followed by an integer token still use the usage message pattern used for other CLI misuse.
- Positive integer `--top` values may use optional leading zeros (for example `--top 02` counts as `2`).
- `top_categories` appears only when `--top` is supplied; it is omitted entirely from success JSON when the flag is absent.
