# Budget alert sort and file read errors

- **REQ-1** `compute_budget_alerts` returns alerts ordered by ascending `month` (`YYYY-MM`) and then by ascending `category` using case-insensitive comparison on each alert’s `category` string (the expense canonical spelling stored in the alert); for `month_category_totals` `{"2024-01": {"food": Decimal('15.00'), "Travel": Decimal('15.00')}}` and `budgets` `{"Travel": Decimal('10.00'), "food": Decimal('10.00')}`, the returned list’s `category` values are `["food", "Travel"]` (not `["Travel", "food"]`, which case-sensitive lexicographic order on those strings would produce).
  `[@test] ../tests/test_expenses_budget_alerts.py`

- **REQ-2** When valid rows in one month yield budget alerts whose printed `category` strings are `Banana` and `apple` (expense-first canonical spellings), `compute_budget_alerts` lists the `apple` alert before the `Banana` alert because `apple` precedes `Banana` under case-insensitive comparison even though uppercase `B` sorts before lowercase `a` in ASCII lexicographic order.
  `[@test] ../tests/test_expenses_budget_alerts.py`

- **REQ-3** Running `python -m factory_target_py.expenses` with a readable expense CSV, `--format json` or no `--format` flag, and `--budgets` pointing to a readable budgets CSV prints JSON whose `budget_alerts` array lists alert objects in the same order as `compute_budget_alerts` returns for the same imported totals and parsed budgets (including case-insensitive category ordering within each month).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** Running `python -m factory_target_py.expenses` with an expense CSV path that cannot be read (for example a missing file) writes exactly one line to stderr equal to the string form of that expense path argument, exits with a non-zero code, prints nothing to stdout, and does not print a Python traceback on stderr.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** Running `python -m factory_target_py.expenses` with a readable expense CSV and `--budgets` followed by a budgets CSV path that cannot be read writes exactly one line to stderr equal to the string form of that budgets path argument, exits with a non-zero code, prints nothing to stdout, and does not print a Python traceback on stderr.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** When `--month` is supplied together with `--budgets`, unreadable expense or budgets paths still follow REQ-4 and REQ-5 (one-line path on stderr, non-zero exit, no traceback, no success stdout); invalid budgets CSV content after a successful read still writes the `ValueError` message to stderr and exits non-zero without success stdout output, unchanged from prior budget-parse behaviour.
  `[@test] ../tests/test_expenses_cli.py`

## Assumptions

- Case-insensitive category ordering for alerts compares `category.casefold()` values; when two alerts share the same month and the same casefolded category (impossible for distinct budget matches), tie-breaking is unspecified because duplicate normalized budget categories are rejected at parse time.
- The stderr line for unreadable files is the path string exactly as derived from the CLI argument (`str` of the `pathlib.Path` built from that argument), with no `[Errno …]` prefix and no exception type name.
- Supersedes py-20261004-16e2 REQ-5: ascending `category` (lexicographic string order) becomes ascending `category` using case-insensitive comparison on each alert’s expense canonical `category` string within each month, after ascending `month`.
- Supersedes py-20261004-16e2 REQ-13: budgets file cannot be read writes an error message to stderr becomes unreadable budgets path writes exactly one stderr line naming that path, with no traceback and no success JSON; `ValueError` from `parse_budgets_csv` still prints the exception message on stderr.
- Supersedes py-20261005-lwd5 assumption: Budget alert ordering by ascending `category` uses the expense canonical strings present in each alert; other CLI, validation, decimal, and month-filter behaviour stays unchanged. becomes Budget alert ordering uses ascending month then ascending `category` compared case-insensitively on expense canonical strings in each alert; other CLI, validation, decimal, and month-filter behaviour stays unchanged except unreadable-file stderr described in this spec.
- Supersedes py-20261005-kj6f REQ-9: Without `--month`, CLI usage messages, positional and `--budgets` argument rules, stderr error text for unreadable files or invalid budgets CSV, and process exit codes for those cases remain unchanged from the expense importer and budget alerts behaviour before the month-filter task becomes Without `--month`, CLI usage messages and positional/`--budgets` argument rules remain as after the month-filter task; unreadable expense or budgets paths write a single stderr line with the path string and no traceback; invalid budgets CSV after a successful read still prints the parse error message on stderr.
- Supersedes py-20261005-mwft REQ-11: Unreadable expense files, unreadable budgets files when `--budgets` is used, and invalid budgets CSV content still produce the same stderr and exit-code behaviour as before this task, regardless of whether `--month` is present. becomes Unreadable expense or budgets paths write exactly one stderr line naming the unreadable path, exit non-zero, emit no traceback, and print no success JSON, with or without `--month`; invalid budgets CSV after a successful read still prints the parse error message on stderr and exits non-zero without success JSON.
- Runtime code uses the Python standard library only; no new third-party dependencies.
