# Expense CLI output formats

- **REQ-1** Running `python -m factory_target_py.expenses` with a readable expense CSV and no `--format` option uses JSON output and produces exactly the same JSON payload, including keys, values, and error records, as the existing expenses CLI behavior for the same input and other supported options.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** Running the expenses CLI with `--format json` and a readable expense CSV produces the same JSON payload as omitting `--format`, including applying `--month` and `--budgets` when supplied.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-3** Running the expenses CLI with `--format csv` and a readable expense CSV prints to stdout a CSV whose first line is exactly `category,total` and whose following lines contain one category total per line in ascending plain string comparison order of category names, with each line formatted as `<category>,<total>` and each total represented as the same two-decimal string used for the corresponding JSON total.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** When `--format csv` and `--month YYYY-MM` are supplied, the CSV category totals include only valid expense rows from the selected month, while the category ordering and two-decimal total formatting remain unchanged.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** When `--format csv` is supplied and the expense CSV contains invalid rows, the CLI writes one stderr line per invalid row in the form `line <n>: <reason>`, using the importer’s line number and reason, prints no JSON to stdout, and exits with status 0 after successfully reading the expense file.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** When `--format csv` is supplied, the CLI does not print month totals, budget alerts, or any other non-category-total records to stdout.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** When the value of `--format` is not `json` or `csv`, or when `--format` has no following value, the CLI writes a usage message to stderr, prints nothing to stdout, and exits with status 1 without reading the expense file.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-8** For both `--format json` and `--format csv`, a readable expense file results in exit status 0, including when the imported expense data contains invalid rows; unreadable input and other existing file or argument errors retain their established non-zero behavior.
  `[@test] ../tests/test_expenses_cli.py`

## Assumptions

- `--format` is an optional flag parsed in any order with the existing `--month` and `--budgets` flags after the expense CSV path; its default is `json`.
- CSV category names are emitted as the canonical category keys produced by expense import, without additional trimming, quoting, or case normalization; category ordering uses ordinary Python string comparison, so uppercase letters sort before lowercase letters.
- In CSV format, `--budgets` may still be parsed and validated as an existing option, but no budget-alert data is emitted; a successfully read expense file with valid arguments still has exit status 0.
- Existing JSON behavior, including reporting all expense validation errors in the JSON `errors` array, remains unchanged when the selected format is `json`.
- Runtime code uses the Python standard library only; no new third-party dependencies.
