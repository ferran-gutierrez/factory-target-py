# Top categories expense summary

- **REQ-1** Running `python -m factory_target_py.expenses` with a readable expense CSV and `--top N` where `N` is a positive decimal integer prints JSON containing a `top_categories` array of at most `N` objects, each with exactly `category` and `total` fields, where `category` is the expense total's canonical category string and `total` is its amount formatted as a string with exactly two decimal places.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** With `--top 2`, when the category totals are built from rows whose totals are `Travel` 5.00, `Food` 12.00, and `Books` 8.00 in that input order, the printed `top_categories` array is `[{"category": "Food", "total": "12.00"}, {"category": "Books", "total": "8.00"}]`, ordered by total descending rather than input order.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-3** When two categories have equal totals, `top_categories` orders them by plain string comparison of their category names, with upper-case letters sorting before lower-case letters; for example equal totals for `apple` and `Banana` are printed as `Banana` before `apple`.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** When `--month YYYY-MM` and `--top N` are both supplied, `top_categories` is computed from the same category totals filtered to the requested month, so rows outside that month do not affect the ranking or totals; for example, with `Food` 20.00 in `2024-03` and `Travel` 7.00 in `2024-04`, `--month 2024-04 --top 1` prints only `Travel` with total `"7.00"`.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** When `N` is larger than the number of categories, `top_categories` contains every category exactly once in the required ordering, and when the selected totals contain no categories, `top_categories` is an empty array.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** When `--top` is followed by `0`, a negative number, a value containing a decimal point, or any other non-decimal-digit text, the CLI writes a clear error message to stderr, writes nothing to stdout, and exits with status 1.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** When `--top` is missing its value, supplied more than once, or supplied in an otherwise invalid command invocation, the CLI writes a usage message to stderr, writes nothing to stdout, and exits non-zero.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-8** Without `--top`, successful CLI output is exactly unchanged from the existing expense CLI behavior, including omission of the `top_categories` key; existing `--month` and `--budgets` behavior remains unchanged.
  `[@test] ../tests/test_expenses_cli.py`

## Assumptions

- `--top` is an optional flag accepted in either order with the existing `--month` and `--budgets` flags.
- Positive integer validation accepts only ASCII decimal digits (`0` through `9`) representing an integer greater than zero; values with signs, whitespace, decimal points, or other characters are rejected.
- Top-category ranking uses the category totals already produced by `import_expenses`, preserving expense-first canonical category spelling and exact `Decimal` arithmetic; serialization uses the existing two-decimal money formatting.
- A valid `--top` value adds `top_categories` to otherwise successful JSON output even when no categories remain after month filtering.
- The invalid-value error message is a concise human-readable line naming that `--top` requires a positive integer; its exact wording is implementation-defined, while the usage-message wording follows existing CLI conventions.
- End-to-end tests are out of scope because `contract.e2e.applies` is false; subprocess-based CLI tests under `tests/test_expenses_cli.py` verify the command-line behavior.
- Runtime code uses the Python standard library only; no new third-party dependencies.
