# CSV expense importer

- **REQ-1** The package exposes `import_expenses(csv_text: str)` in `factory_target_py.expenses` that returns a tuple `(category_totals, month_totals, errors)` where `category_totals` maps each category string to the sum of valid row amounts, `month_totals` maps each `YYYY-MM` string to the sum of valid row amounts, and `errors` is a list of records each with integer `line` (1-based line index in `csv_text`) and string `reason`.
  `[@test] ../tests/test_expenses_import.py`

- **REQ-2** The first line of `csv_text` is a header row with four comma-separated fields whose names are `date`, `category`, `description`, and `amount` compared case-insensitively; that line is not validated as an expense row and is not included in totals.
  `[@test] ../tests/test_expenses_import.py`

- **REQ-3** Each subsequent non-empty data row must have exactly four fields after standard CSV parsing; otherwise the row is skipped and `errors` contains an entry for that row's line number with reason `wrong number of columns`.
  `[@test] ../tests/test_expenses_import.py`

- **REQ-4** For each data row, leading and trailing whitespace is stripped from every field before validation; a row whose fields are all empty after stripping is skipped without adding an error.
  `[@test] ../tests/test_expenses_import.py`

- **REQ-5** A data row is invalid if `date` is not exactly `YYYY-MM-DD` or does not denote a valid Gregorian calendar date; such rows are skipped and `errors` contains reason `invalid date`.
  `[@test] ../tests/test_expenses_import.py`

- **REQ-6** A data row is invalid if `category` is empty after stripping; such rows are skipped and `errors` contains reason `empty category`.
  `[@test] ../tests/test_expenses_import.py`

- **REQ-7** A data row is invalid if `description` is empty after stripping; such rows are skipped and `errors` contains reason `empty description`.
  `[@test] ../tests/test_expenses_import.py`

- **REQ-8** A data row is invalid if `amount` is not a decimal number or is less than or equal to zero; such rows are skipped and `errors` contains reason `invalid amount`.
  `[@test] ../tests/test_expenses_import.py`

- **REQ-9** When a data row fails more than one validation rule, only one error is recorded for that row, checked in the order date, category, description, then amount.
  `[@test] ../tests/test_expenses_import.py`

- **REQ-10** Valid rows add their parsed amount to `category_totals` under the stripped category string and to `month_totals` under the month derived from the row date (`YYYY-MM`); multiple valid rows with the same category or month are summed.
  `[@test] ../tests/test_expenses_import.py`

- **REQ-11** Amounts in returned totals use numeric values that equal the mathematical sum of parsed row amounts (tests compare with standard decimal/float equality suitable for money literals used in fixtures).
  `[@test] ../tests/test_expenses_import.py`

- **REQ-12** Importing a fixture CSV that mixes valid and invalid data rows produces the expected category totals, month totals, and a complete set of per-line errors with line numbers matching the fixture file.
  `[@test] ../tests/test_expenses_mixed_fixture.py`

- **REQ-13** Running `python -m factory_target_py.expenses` with exactly one argument, a path to a readable CSV file, reads the file as text, calls `import_expenses`, and prints to stdout a single JSON object with keys `category_totals`, `month_totals`, and `errors` (same shapes as REQ-1); on success the process exit code is 0.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-14** Running `python -m factory_target_py.expenses` with zero arguments or more than one argument writes a usage message to stderr and exits with a non-zero code.
  `[@test] ../tests/test_expenses_cli.py`

## Assumptions

- `pyproject.toml` cannot gain `[project.scripts]` or other entry-point configuration under the factory contract; the CLI is exposed only as `python -m factory_target_py.expenses`, not as an installed console script name.
- Runtime code uses the Python standard library only (`csv`, `datetime`, `decimal` or `float`, `json`, `sys`, `pathlib` as needed); no third-party CSV or date libraries.
- The header row must be present as line 1; files with no header are out of scope.
- Category and month aggregation keys are case-sensitive and use stripped field text as stored in the CSV (no normalization beyond whitespace trimming).
- Invalid rows do not contribute to either totals map; valid rows with zero categories/months never occur because amount must be strictly positive.
- CLI JSON output encodes totals with JSON numbers; error objects use `"line"` and `"reason"` keys only.
- Mixed-fixture tests live beside unit tests under `tests/` and may load CSV content from a string constant or a small file in `tests/fixtures/` if the implementation adds that path under allowed directories.
