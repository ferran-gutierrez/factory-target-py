# CSV expense importer

- **REQ-1** The package exposes `import_expenses(csv_text: str)` in `factory_target_py.expenses` that returns a tuple `(category_totals, month_totals, month_category_totals, errors)` where `category_totals` maps each expense canonical category string to the `decimal.Decimal` sum of valid row amounts (one key per normalized category: stripped text equal case-insensitively share the key from the first valid row in file order), `month_totals` maps each `YYYY-MM` string to the `decimal.Decimal` sum of valid row amounts, `month_category_totals` maps each `YYYY-MM` string to a dict of those same canonical category strings to `decimal.Decimal` sums for that month, and `errors` is a list of records each with integer `line` (1-based line index in `csv_text`) and string `reason`.
  `[@test] ../tests/test_expenses_import.py`

- **REQ-2** The first line of `csv_text` is a header row with four comma-separated fields whose names are `date`, `category`, `description`, and `amount` compared case-insensitively; that line is not validated as an expense row and is not included in totals.
  `[@test] ../tests/test_expenses_import.py`

- **REQ-3** Each subsequent non-empty data row must have exactly four fields after standard CSV parsing; otherwise the row is skipped and `errors` contains an entry for that row's line number with reason `wrong number of columns`.
  `[@test] ../tests/test_expenses_import.py`

- **REQ-4** For each data row, leading and trailing whitespace is stripped from every field before validation; a row whose fields are all empty after stripping is skipped without adding an error.
  `[@test] ../tests/test_expenses_import.py`

- **REQ-5** A data row is invalid if `date` is not exactly `YYYY-MM-DD` or does not denote a valid Gregorian calendar date; such rows are skipped and `errors` contains reason `invalid date`.
  `[@test] ../tests/test_expenses_import.py`

- **REQ-6** A data row is invalid if `category` is empty after stripping; such rows are skipped and `errors` contains reason `empty category`.
  `[@test] ../tests/test_expenses_import.py`

- **REQ-7** A data row is invalid if `description` is empty after stripping; such rows are skipped and `errors` contains reason `empty description`.
  `[@test] ../tests/test_expenses_import.py`

- **REQ-8** A data row is invalid if `amount` is not a decimal number or is less than or equal to zero; such rows are skipped and `errors` contains reason `invalid amount`.
  `[@test] ../tests/test_expenses_import.py`

- **REQ-9** When a data row fails more than one validation rule, only one error is recorded for that row, checked in the order date, category, description, then amount.
  `[@test] ../tests/test_expenses_import.py`

- **REQ-10** Valid rows add their parsed amount to `category_totals` under the canonical category key for their normalized category (stripped `category` fields that match case-insensitively share the first valid row’s stripped spelling) and to `month_totals` under the month derived from the row date (`YYYY-MM`); multiple valid rows with the same normalized category or the same month are summed.
  `[@test] ../tests/test_expenses_import.py`

- **REQ-11** Amounts in returned totals use `decimal.Decimal` values that equal the exact mathematical sum of parsed row amounts; for example two valid rows in the same category with amounts `0.10` and `0.20` yield category total `Decimal('0.30')`.
  `[@test] ../tests/test_expenses_import.py`

- **REQ-12** Importing a fixture CSV that mixes valid and invalid data rows produces the expected category totals, month totals, and a complete set of per-line errors with line numbers matching the fixture file.
  `[@test] ../tests/test_expenses_mixed_fixture.py`

- **REQ-13** Running `python -m factory_target_py.expenses` with one positional argument giving a path to a readable expense CSV file, and optionally `--format json`, `--format csv`, `--month YYYY-MM`, and/or `--budgets` followed by a budgets CSV path, reads the expense file as text, calls `import_expenses`, applies month filtering when `--month` is present, and prints the format selected by the later expense CLI requirements; `--format json` is the default and on success the process exit code is 0.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-14** Running `python -m factory_target_py.expenses` with zero positional arguments, more than one positional argument, `--budgets` without a following path, `--month` without a following value, `--format` without a following value, an invalid `--month` value, an unsupported `--format` value, or unrecognized optional arguments writes a usage message to stderr, prints nothing to stdout, and exits with status 1.
  `[@test] ../tests/test_expenses_cli.py`

## Assumptions

- `pyproject.toml` cannot gain `[project.scripts]` or other entry-point configuration under the factory contract; the CLI is exposed only as `python -m factory_target_py.expenses`, not as an installed console script name.
- Runtime code uses the Python standard library only (`csv`, `datetime`, `decimal`, `json`, `sys`, `pathlib` as needed); money uses `decimal.Decimal`, not `float`; no third-party CSV or date libraries.
- The header row must be present as line 1; files with no header are out of scope.
- Month aggregation keys remain `YYYY-MM` from valid row dates. Category totals merge rows whose stripped categories match case-insensitively under the stripped category text from the first valid row in file order for that normalized category.
- Invalid rows do not contribute to either totals map; valid rows with zero categories/months never occur because amount must be strictly positive.
- CLI JSON output encodes money totals as two-decimal strings; error objects use `"line"` and `"reason"` keys only.
- Mixed-fixture tests live beside unit tests under `tests/` and may load CSV content from a string constant or a small file in `tests/fixtures/` if the implementation adds that path under allowed directories.
