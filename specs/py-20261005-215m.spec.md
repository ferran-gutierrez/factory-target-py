# Expense output formats

- **REQ-1** Running `python -m factory_target_py.expenses` with a readable expense CSV and either no `--format` option or `--format json` prints the same JSON object and values as the existing default output, including two-decimal money strings, validation errors, month filtering, and optional budget alerts.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** Running `python -m factory_target_py.expenses` with a readable expense CSV and `--format csv` prints to stdout only the category totals as CSV with the exact first line `category,total`, followed by one line per category in ascending plain string order; for categories `apple` and `Banana`, the output orders `Banana` before `apple`.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-3** In CSV format, each category total is printed as `<category>,<total>`, where `<total>` is the corresponding JSON-format money string with exactly two decimal places, and categories are taken from the same filtered category totals that JSON output would use.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** When `--format csv` and `--month YYYY-MM` are supplied, the CSV output contains only category totals for valid expense rows in that month; for rows totaling `5.00` in `2024-03` and `7.00` in `2024-04`, `--month 2024-04` prints `Food,7.00` and does not print `Food,12.00`.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** When `--format csv` processes a readable expense CSV containing invalid rows, it prints no JSON to stdout, reports each invalid row on stderr as exactly `line <n>: <reason>` using the same line number and reason that JSON output reports, and exits with status 0.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** When `--format` has no following value or its value is anything other than `json` or `csv`, the CLI writes a usage message to stderr, writes nothing to stdout, and exits with status 1.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** With a readable expense input file, both omitted/JSON format and CSV format exit with status 0 even when the import contains invalid rows; an unreadable input file remains a non-zero file-read error in either format.
  `[@test] ../tests/test_expenses_cli.py`
