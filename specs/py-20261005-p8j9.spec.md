# Expense CLI output format

- **REQ-1** Running `python -m factory_target_py.expenses` with a readable expense CSV and no `--format` flag prints to stdout the same JSON object as before this task (including optional `--month` and `--budgets` behaviour) and exits with code 0.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** Running with `--format json` and a readable expense CSV prints to stdout the same JSON as REQ-1 for the same expense file and optional flags, and exits with code 0.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-3** Running with `--format csv` and a readable expense CSV prints to stdout only category totals as CSV: the first line is exactly `category,total`, followed by one line per category key in `category_totals` after any `--month` filtering, ordered by ascending category name using plain string comparison (Unicode code point order, so uppercase letters sort before lowercase letters in the same position), each line formatted as `<category>,<total>` where `<total>` is the same two-decimal string that would appear for that category in JSON `category_totals`, and exits with code 0.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** When `--format csv` and `--month YYYY-MM` are both supplied, the CSV rows reflect `category_totals` after month filtering (only spending in that month), using the same canonical category keys and two-decimal strings as JSON output for that filter.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** When `--format csv` and the expense file was read successfully, each import validation error is written to stderr as exactly one line `line <n>: <reason>` using the same integer line number and reason string as the corresponding object in the JSON `errors` array; no JSON is printed to stdout.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** When `--format csv` and a readable expense CSV contains both valid rows and invalid rows, stdout contains only the CSV from REQ-3 for aggregated valid data, stderr contains one line per error as in REQ-5, and the exit code is 0.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** When `--format csv` and valid rows yield at least two distinct canonical category keys whose plain string sort order differs from case-insensitive lexicographic order (for example canonical categories `alpha` and `Beta` with totals that require both lines in the output), the CSV data lines appear in plain string ascending order (`Beta` before `alpha`), not case-insensitive order.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-8** Running with `--format` followed by a value other than `json` or `csv`, with `--format` as the last argument (no value), or with a duplicate `--format` flag, writes a usage message to stderr, prints nothing to stdout, and exits with status 1.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-9** Optional `--format`, `--month`, and `--budgets` flags may appear in any order after the expense CSV path; for example `--format csv --month 2024-05` and `--month 2024-05 --format csv` produce the same CSV totals for the same files.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-10** When `--format csv` and `--budgets` with a readable budgets CSV are supplied, a successful run still prints only the category totals CSV to stdout (no `budget_alerts` in stdout); unreadable budgets paths, invalid budgets CSV content, and duplicate budget categories follow the same stderr and exit-code rules as JSON mode, with no success CSV on stdout when the process exits non-zero.
  `[@test] ../tests/test_expenses_cli.py`
