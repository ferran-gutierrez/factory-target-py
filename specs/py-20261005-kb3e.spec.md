# Expenses CLI output formats

- **REQ-1** Running `python -m factory_target_py.expenses` with a readable expense CSV and no `--format` option, or with `--format json`, produces the existing JSON output unchanged, including category totals, month totals, validation errors, optional month filtering, and optional budget alerts.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** Running `python -m factory_target_py.expenses` with `--format csv` and a readable expense CSV prints to stdout a CSV document containing only the category totals: the first line is exactly `category,total`, followed by one line per category formatted as `<category>,<total>`, with totals represented as the same two-decimal strings used by JSON output.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-3** CSV category-total rows are ordered by category name using plain string comparison, so uppercase letters sort before lowercase letters; the output reflects the category totals after the requested `--month` filter when `--month` is supplied.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** In CSV format, every invalid expense row is reported to stderr as one line in the form `line <n>: <reason>`, using the same line number and reason that JSON output would include in its `errors` array, no JSON is printed to stdout, and a readable expense file results in exit status 0.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** When `--format` is followed by any value other than `json` or `csv`, or has no following value, the CLI prints a usage message to stderr, prints nothing to stdout, and exits with status 1.
  `[@test] ../tests/test_expenses_cli.py`

## Assumptions

- `--format` is an order-independent optional flag alongside the existing `--month` and `--budgets` flags; omitting it is equivalent to `--format json`.
- CSV output uses the existing category keys and money serialization rules, does not quote fields unless required by standard CSV formatting, and uses a final newline.
- CSV output is a presentation mode: it suppresses the JSON payload and emits only category totals, while existing expense-file reading, validation, month filtering, and optional budget-input processing remain otherwise unchanged.
- Runtime code uses the Python standard library only; no new third-party dependencies are required.
