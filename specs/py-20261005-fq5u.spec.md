# Expense CLI output format

- **REQ-1** Running `python -m factory_target_py.expenses` with a readable expense CSV and no `--format` flag prints to stdout the same JSON object and uses exit code `0` on success as before this task (implicit default format is `json`).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** Running with `--format json` prints to stdout the same JSON payload as when `--format` is omitted for the same expense CSV and optional `--month` and `--budgets` arguments.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-3** Running with `--format csv` and a readable expense CSV prints to stdout only CSV text whose first line is exactly `category,total`, followed by one line per category present in the JSON `category_totals` map that `--format json` would use for the same inputs, ordered by ascending category name using plain string comparison (for example `Banana` sorts before `apple` because uppercase letters precede lowercase in ASCII order), each data line formatted as `<category>,<total>` where `<total>` is the same two-decimal string value as in JSON `category_totals`, and exits with code `0` when the expense file was read.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** Running with `--format csv` and `--month YYYY-MM` uses the same month-filtered `category_totals` as `--format json` with the same month (CSV rows reflect filtered totals only).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** Running with `--format csv` on an expense CSV that yields one or more import validation errors prints no JSON to stdout; stderr contains exactly one line per error formatted `line <n>: <reason>` where `<n>` and `<reason>` match the `line` and `reason` fields of the corresponding entries in the JSON `errors` array produced for `--format json` on the same file; stdout still contains the CSV header and one row per category from valid rows; exit code is `0` when the expense file was read.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** Running with `--format csv` on valid rows whose canonical categories are `apple` and `Banana` (after case-insensitive merging) prints CSV data lines in order `Banana,<total>` then `apple,<total>` (plain string sort, not case-insensitive sort).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** Running with `--format` followed by any value other than `json` or `csv`, with `--format` as the last argument and no following value, or with a duplicate `--format` flag, writes a usage message to stderr, prints nothing to stdout, and exits with status `1`.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-8** Optional `--format` may appear in any order with `--month` and `--budgets` after the expense CSV path; for example `--format csv --month 2024-05` and `--month 2024-05 --format csv` produce the same CSV category totals for the same files.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-9** When `--format csv` and `--budgets` are both supplied with readable inputs, stdout remains CSV category totals only (no JSON and no budget alert fields on stdout); unreadable expense or budgets paths, invalid budgets CSV content, and invalid `--month` values still follow the same stderr and exit-code rules as when `--format` is omitted or `json`.
  `[@test] ../tests/test_expenses_cli.py`
