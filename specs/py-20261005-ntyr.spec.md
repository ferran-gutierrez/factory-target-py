# Expense CLI output format

- **REQ-1** When `python -m factory_target_py.expenses` is run with a readable expense CSV path and `--format` is omitted or set to `json`, stdout is exactly the same JSON object (keys, field order within objects, money string formatting, optional `month` and `budget_alerts`, and `errors` content) as on the branch before this task for the same expense path and the same optional `--month` and `--budgets` arguments.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** Running with `--format json` explicitly produces the same stdout JSON as when `--format` is omitted for the same arguments.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-3** Running with `--format csv` and a readable expense CSV writes to stdout only CSV text: the first line is exactly `category,total`, then one line per category in `category_totals` after any `--month` filtering, ordered by ascending category name using plain string (byte/Unicode code point) comparison where upper-case letters sort before lower-case (for example categories `food` and `Travel` appear as lines `Travel,<total>` then `food,<total>`, not `food` before `Travel` as case-insensitive order would).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** Each `--format csv` data line is `<category>,<total>` where `<category>` is the canonical category key from import (including expense-first spelling) and `<total>` is the same two-decimal string that appears for that category in the JSON `category_totals` map when `--format json` is used with the same inputs (for example `"12.00"`).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** When `--format csv` is used together with `--month YYYY-MM`, the CSV rows reflect `category_totals` restricted to that month in the same way as JSON output with `--format json` and the same `--month` value (for example rows in `2024-03` and `2024-04` both in `Food` with `--month 2024-04` yield a single `Food,<filtered-total>` line, not the all-months total).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** When `--format csv` is used and the expense file contains invalid data rows, each import error is written to stderr as one line `line <n>: <reason>` using the same integer line number and reason string as the corresponding object in the JSON `errors` array for `--format json` on the same file; stdout contains the CSV from REQ-3 and REQ-4 for valid rows only, no JSON is printed, and the exit code is 0 because the expense file was read successfully.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** When `--format csv` is used with an expense CSV that includes at least two categories whose order differs under case-insensitive comparison versus plain string comparison (for example canonical keys `apple` and `Banana`), stdout CSV line order follows plain string ascending order on the category keys (`Banana,...` before `apple,...`).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-8** Running with `--format` as the last token (no value following), with `--format` followed by an empty value where the parser would consume the next argv token, or with `--format` set to any value other than `json` or `csv`, writes a usage message to stderr, prints nothing to stdout, and exits with status code 1.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-9** Optional `--format` may appear in any order relative to `--month` and `--budgets` after the expense CSV path; duplicate `--format` tokens or duplicate `--month` / `--budgets` tokens still produce a usage message on stderr, empty stdout, and exit code 1.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-10** When `--format csv` is supplied together with `--budgets`, unreadable expense or budgets paths, invalid budgets CSV after a successful read, and invalid `--month` values behave the same as with `--format json` (stderr content and non-zero exit, no success stdout); when both budget inputs succeed, stdout is still only the category totals CSV from REQ-3 and REQ-4 with no budget alert fields on stdout.
  `[@test] ../tests/test_expenses_cli.py`

- `pyproject.toml` cannot gain console script entry points; the CLI remains `python -m factory_target_py.expenses`.
