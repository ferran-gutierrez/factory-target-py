# Expense budget alerts

- **REQ-1** The package exposes `compute_budget_alerts(month_category_totals: dict[str, dict[str, decimal.Decimal]], budgets: dict[str, decimal.Decimal]) -> list[dict]` in `factory_target_py.expenses` that returns one alert dict per `(month, expense canonical category)` pair where a budget row’s stripped category matches that expense category case-insensitively and the month-and-category total is strictly greater than that budget limit; each alert dict has string keys `month`, `category` (the expense canonical category string), and `total`, `limit`, and `amount_over` as `decimal.Decimal` where `total` is the sum for that month and canonical category, `limit` is the matched budget limit, and `amount_over` equals `total - limit`.
  `[@test] ../tests/test_expenses_budget_alerts.py`

- **REQ-2** `compute_budget_alerts` never emits an alert for a category that is absent from `budgets`, even when that category appears in `month_category_totals`.
  `[@test] ../tests/test_expenses_budget_alerts.py`

- **REQ-3** `compute_budget_alerts` never emits an alert when the month-and-category total is less than or equal to the budget limit for that category.
  `[@test] ../tests/test_expenses_budget_alerts.py`

- **REQ-4** `compute_budget_alerts` treats a missing inner category key as a total of zero for that month; a budgeted category with no spending in a month therefore produces no alert.
  `[@test] ../tests/test_expenses_budget_alerts.py`

- **REQ-5** Alerts returned by `compute_budget_alerts` are ordered by ascending `month` (`YYYY-MM`) and then ascending `category` using case-insensitive comparison on each alert’s `category` string (the expense canonical spelling in the alert dict).
  `[@test] ../tests/test_expenses_budget_alerts.py`

- **REQ-6** `import_expenses(csv_text: str)` returns a four-tuple `(category_totals, month_totals, month_category_totals, errors)` where `month_category_totals` maps each `YYYY-MM` string to a dict mapping expense canonical category strings (case-insensitive merge with first valid row spelling, consistent with `category_totals`) to the `decimal.Decimal` sum of valid row amounts for that month and normalized category, and valid rows update `month_category_totals` consistently with existing category and month aggregation rules.
  `[@test] ../tests/test_expenses_budget_alerts.py`

- **REQ-7** The package exposes `parse_budgets_csv(csv_text: str) -> dict[str, Decimal]` that reads a CSV whose first line is a header with fields `category` and `limit` compared case-insensitively; each subsequent non-empty data row must have exactly two fields after standard CSV parsing with leading and trailing whitespace stripped from each field, maps the stripped category string from each valid row to a parsed `decimal.Decimal` limit with at most one row per normalized category (strip plus case-insensitive equality), and returns the combined mapping for all valid data rows.
  `[@test] ../tests/test_expenses_budget_alerts.py`

- **REQ-8** A budget data row is invalid if the stripped category is empty or if `limit` is not a decimal number or is less than or equal to zero; `parse_budgets_csv` raises `ValueError` when any invalid data row is present.
  `[@test] ../tests/test_expenses_budget_alerts.py`

- **REQ-9** A budget data row whose fields are all empty after stripping is skipped without error; the header row is never validated as a budget row.
  `[@test] ../tests/test_expenses_budget_alerts.py`

- **REQ-10** When `parse_budgets_csv` encounters two or more data rows whose stripped categories are equal case-insensitively, it raises `ValueError` with message `duplicate category` and does not return a mapping.
  `[@test] ../tests/test_expenses_budget_alerts.py`

- **REQ-11** Running `python -m factory_target_py.expenses` with one positional argument (expense CSV path) and no optional flags behaves as before budget alerts: reads the expense file, calls `import_expenses`, prints JSON with keys `category_totals`, `month_totals`, and `errors` only where money values in the totals maps are two-decimal strings, and exits 0 on success.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-12** Running `python -m factory_target_py.expenses` with one positional expense CSV path and `--budgets` followed by a path to a readable budgets CSV reads both files, parses budgets with `parse_budgets_csv`, computes alerts via `compute_budget_alerts` from `month_category_totals` restricted to the `--month` value when that flag is present otherwise from the full import result, and prints JSON that includes the keys from REQ-11 plus `budget_alerts` (a JSON array of alert objects whose `total`, `limit`, and `amount_over` are two-decimal strings), and includes `"month"` when `--month` is present; on success the exit code is 0.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-13** When `--budgets` is supplied and the budgets CSV path cannot be read, the CLI writes exactly one line to stderr equal to the string form of that budgets path, exits with a non-zero code, does not print a Python traceback, and prints no success JSON to stdout; when the budgets file is readable but `parse_budgets_csv` raises `ValueError`, the CLI writes the exception message to stderr, exits with a non-zero code, and prints no success JSON to stdout.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-14** Running `python -m factory_target_py.expenses` with zero positional arguments, more than one positional argument, `--budgets` without a following path, `--month` without a following value, an invalid `--month` value, `--top` without a following value, duplicate `--top`, or unrecognized optional arguments writes a usage message to stderr and exits with a non-zero code; an invalid `--top` N value writes a dedicated error message to stderr mentioning `--top`, prints no success JSON to stdout, and exits with status code 1.
  `[@test] ../tests/test_expenses_cli.py`

## Assumptions

- Per-category budgets apply to every calendar month independently; there is no rollover or shared pool across months.
- Budget limits use the same numeric parsing rules as expense amounts (decimal syntax, strictly positive values).
- `month_category_totals` keys use `YYYY-MM` derived from valid expense row dates, matching existing month aggregation.
- Budget categories match expense canonical categories when stripped forms are equal case-insensitively; duplicate normalized budget rows raise `ValueError` with message `duplicate category`.
- `pyproject.toml` cannot gain console script entry points; the CLI remains `python -m factory_target_py.expenses` with an added optional `--budgets` flag.
- Runtime code uses the Python standard library only; no new third-party dependencies.
- End-to-end tests are out of scope for this task (`contract.e2e.applies` is false); CLI behavior is covered by unit-style subprocess tests under `tests/`.
- Existing tests that unpack a three-tuple from `import_expenses` will be updated in the test-author stage to match the four-tuple return defined in REQ-6.
