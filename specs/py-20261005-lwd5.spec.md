# Case-insensitive expense categories

- **REQ-1** `import_expenses` treats two valid data rows as the same category when their `category` fields are equal after stripping leading and trailing whitespace and comparing case-insensitively; all such rows contribute to a single key in `category_totals` and in each relevant inner map of `month_category_totals`, and that key is the stripped `category` text from the first valid row in file order for that normalized category (for example rows on lines 2 and 3 with categories ` Food` and `FOOD ` yield one entry keyed `Food`, not separate `Food` and `FOOD` keys).
  `[@test] ../tests/test_expenses_import.py`

- **REQ-2** When valid rows in the same calendar month use categories `travel`, ` Travel`, and `TRAVEL` with amounts `1.00`, `2.00`, and `3.00` and the first of those rows in file order has stripped category `travel`, `month_category_totals` for that month maps `travel` to `Decimal('6.00')` and does not include separate keys for the other spellings.
  `[@test] ../tests/test_expenses_import.py`

- **REQ-3** `compute_budget_alerts` matches a budget category to month-and-category totals when the stripped budget category and the stripped expense canonical category are equal case-insensitively; for `month_category_totals` `{"2024-05": {"Food": Decimal('15.00')}}` and `budgets` parsed from a row ` FOOD ,10.00`, it emits one alert with `category` set to `Food`, `limit` `Decimal('10.00')`, and `amount_over` `Decimal('5.00')`.
  `[@test] ../tests/test_expenses_budget_alerts.py`

- **REQ-4** `parse_budgets_csv` raises `ValueError` with message `duplicate category` when two non-skipped budget data rows normalize to the same category (for example rows `Food,100` and `FOOD,200`, or two rows both stripped to `Food`), in the same way as other invalid budget data rows.
  `[@test] ../tests/test_expenses_budget_alerts.py`

- **REQ-5** Running `python -m factory_target_py.expenses` with an expense CSV whose first valid row has category ` Food` and a later valid row has `food`, default or `--format json`, and no other optional flags, prints JSON whose `category_totals` object has a single key `Food` (not `food`) and a two-decimal string value equal to the sum of both rows; `--format csv` emits one CSV row `Food,<same-total>`.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** Running `python -m factory_target_py.expenses` with a readable expense CSV and `--budgets` pointing to a budgets CSV containing rows `Food,10.00` and `food,20.00` writes an error message to stderr, exits with a non-zero code, and prints no success stdout (whether the output format is json or csv).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** When `--month YYYY-MM` and `--budgets` are both supplied with default or `--format json`, budget alert computation and filtered `category_totals` still use case-insensitive category matching and expense-first canonical spelling; for example expense rows `2024-05-01,FOOD,A,8.00` then `2024-05-02,food,B,4.00` with budget row ` Food ,10.00` and `--month 2024-05` yields `"category_totals": {"FOOD": "12.00"}` and a single `budget_alerts` entry with `"category": "FOOD"` and `"amount_over": "2.00"`; `--format csv` with the same inputs prints `FOOD,12.00` on stdout when budget inputs succeed.
  `[@test] ../tests/test_expenses_cli.py`

## Assumptions

- Category normalization for matching and merging is strip plus case-insensitive comparison (equivalent to comparing `stripped.casefold()` values); month keys remain case-sensitive `YYYY-MM` strings derived from valid row dates.
- Canonical category strings in expense totals and in budget alert `category` fields always use the stripped text from the first valid expense row for that normalized category; budget CSV keys returned by `parse_budgets_csv` use the stripped text from the single budget row for each normalized category (duplicate normalized rows are rejected).
- Supersedes py-20261004-6bjo REQ-1: category and month_category_totals keys are distinct stripped category strings per row becomes canonical stripped category from first valid row per normalized category with case-insensitive merging in all totals maps.
- Supersedes py-20261004-6bjo REQ-10: valid rows add amounts under the stripped category string becomes valid rows add amounts under the canonical category key for their normalized category (first valid row spelling in file order).
- Supersedes py-20261004-6bjo assumption: Category and month aggregation keys are case-sensitive and use stripped field text as stored in the CSV (no normalization beyond whitespace trimming). becomes Month keys stay `YYYY-MM` from row dates; category totals merge rows whose stripped categories match case-insensitively under the first valid row’s stripped category text.
- Supersedes py-20261004-16e2 REQ-1: alerts when category exists in budgets with case-sensitive key lookup becomes alerts when a budget category matches an expense canonical category case-insensitively after strip, with alert `category` set to the expense canonical string.
- Supersedes py-20261004-16e2 REQ-6: month_category_totals inner keys are stripped category strings per row becomes inner keys are expense canonical category strings with case-insensitive merging consistent with category_totals.
- Supersedes py-20261004-16e2 REQ-7: parse_budgets maps each stripped category from valid rows with possible duplicates resolved later becomes parse_budgets maps each stripped category from valid rows with at most one row per normalized category.
- Supersedes py-20261004-16e2 REQ-10: last budget row wins for duplicate stripped category becomes raises ValueError with message duplicate category when two data rows share the same normalized category.
- Supersedes py-20261004-16e2 assumption: Category strings in budgets are matched case-sensitively against expense categories (stripped, no further normalization), consistent with the expense importer spec. becomes Budget categories match expense canonical categories when stripped forms are equal case-insensitively; duplicate normalized budget rows raise ValueError.
- Budget alert ordering uses ascending `month` then ascending `category` compared case-insensitively on the expense canonical strings in each alert; other CLI, validation, decimal, and month-filter behaviour stays unchanged except unreadable expense or budgets paths report a single stderr line with the path string and no traceback.
- Runtime code uses the Python standard library only; no new third-party dependencies.
