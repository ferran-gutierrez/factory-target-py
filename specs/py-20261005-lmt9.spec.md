# Top categories expense summary

- **REQ-1** Running `python -m factory_target_py.expenses` with one expense CSV path and `--top N` accepts `N` as a positive integer written only with decimal digits and, on success, adds a `top_categories` JSON array to the existing output.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** Each object in `top_categories` has exactly the keys `category` and `total`, where `category` is an expense category name from the same category totals used by the output and `total` is that category amount serialized as a string with exactly two decimal places.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-3** `top_categories` uses the category totals after applying `--month YYYY-MM` when `--month` is supplied, so it contains only categories with spending in the selected month and reflects the selected-month totals.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** `top_categories` is ordered by total descending and, when totals are equal, by category name ascending using plain string comparison, where uppercase letters sort before lowercase letters.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** When `N` is larger than the number of available categories, `top_categories` contains every available category, and when there are no available categories it is an empty array.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** When `--top` is followed by zero, a negative number, a value containing a decimal point, or any other non-digit text, the CLI writes a clear error identifying the invalid `--top` value to stderr, writes nothing to stdout, and exits with status 1.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** Without `--top`, the CLI JSON output and behavior remain exactly as before for the same expense CSV and existing optional flags, with no `top_categories` entry.
  `[@test] ../tests/test_expenses_cli.py`

## Assumptions

- `--top` may be combined with `--month` and `--budgets` and may appear in any order among the existing optional flags.
- Top-category totals use the expense category names and canonicalization already established by the importer; no new category normalization rules are introduced.
- The existing standard-library-only runtime dependency policy remains unchanged.
