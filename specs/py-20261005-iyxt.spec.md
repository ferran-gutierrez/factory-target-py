# Expense CLI top categories

- **REQ-1** Running `python -m factory_target_py.expenses` with a readable expense CSV and without `--top` prints success JSON that omits the `top_categories` key entirely (same keys and values as before this task for the same `--month` and `--budgets` inputs).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** Running with `--top` followed by a valid positive integer `N` (decimal digits only, value strictly greater than zero, for example `--top 2`) adds `"top_categories"` to the success JSON: a JSON array of at most `N` objects, each with string keys `"category"` and `"total"`, where `"total"` is the same two-decimal money string as the matching entry in the printed `"category_totals"` object for that category name.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-3** Each `"category"` in `top_categories` is an expense canonical category string taken from the same filtered `category_totals` map the CLI already prints (full import totals when `--month` is absent, month-filtered totals when `--month YYYY-MM` is present); for example with rows `2024-03-15,Food,A,5.00` and `2024-04-01,Travel,B,7.00`, `--month 2024-04 --top 5` yields `"top_categories": [{"category": "Travel", "total": "7.00"}]` and no `Food` entry.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** `top_categories` is ordered by `"total"` interpreted as a decimal money string in descending numeric order, and when two categories share the same total, by `"category"` ascending using plain Python string comparison (lexicographic on Unicode code points, so uppercase letters sort before lowercase); for example with categories `apple` and `Banana` both totaling `"15.00"`, `--top 3` lists `Banana` before `apple`.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** When `N` is greater than the number of categories in the filtered `category_totals`, `top_categories` includes every such category (length equals the number of keys in `category_totals`); for example three distinct categories with `--top 10` yields a three-element array.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** When the filtered `category_totals` object is empty (including `--month` on a month with no valid rows), success JSON has `"top_categories": []`.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** When `--top` is followed by `0`, a negative integer, a value containing a decimal point, or any token that is not a non-empty string of decimal digits whose integer value is strictly positive (for example `--top 0`, `--top -1`, `--top 1.5`, `--top two`), the CLI writes a clear error message to stderr (at least one non-empty line that is not the generic usage line), prints nothing to stdout, and exits with status code `1`.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-8** Running with `--top` as the last argument (no value following), a second `--top` flag when one was already parsed, or any unrecognized optional token after the expense CSV path writes the CLI usage message to stderr and exits with a non-zero code without printing success JSON to stdout.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-9** Optional `--top N` may appear in any order relative to `--month` and `--budgets` after the expense CSV path; for the same files and flags, reordering only permutes optional arguments and leaves the success JSON (including `top_categories`) unchanged.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-10** When `--budgets` is also supplied, success JSON still includes `budget_alerts` as before, and `top_categories` is built only from `category_totals` (not from budget data); unreadable expense or budgets paths and invalid budgets CSV after a successful read still follow prior stderr and exit behaviour regardless of `--top`.
  `[@test] ../tests/test_expenses_cli.py`
