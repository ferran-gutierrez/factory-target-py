# Expense CLI output formats

- **REQ-1** Running `python -m factory_target_py.expenses` with a readable expense CSV and no `--format` option, or with `--format json`, prints the same JSON object as the existing expenses CLI, including its existing keys, values, validation errors, and month-filter behavior, and exits with status 0 when the expense file was read.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** Running `python -m factory_target_py.expenses` with `--format csv` and a readable expense CSV prints to stdout only a CSV document whose first line is `category,total`, followed by one line per category in ascending plain string comparison order, with each line formatted as `<category>,<total>` and each total represented by the same two-decimal money string used by JSON output.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-3** When `--format csv` is combined with `--month YYYY-MM`, the CSV category totals include only valid expense rows from that month, using the same month filtering as JSON output; the CSV stdout contains no JSON, month-total object, or budget-alert object.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** When `--format csv` is selected, every invalid expense row is reported on stderr as exactly one line `line <n>: <reason>` using the importer's existing line number and reason, no JSON is printed to stdout, and the process exits with status 0 when the expense file was read.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** When `--format` is supplied without a value, or with any value other than `json` or `csv`, the CLI prints a usage message to stderr, prints nothing to stdout, and exits with status 1.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** The `--format` option can be supplied alongside the existing `--month` and `--budgets` options in any order after the expense CSV path; JSON remains the default, and CSV stdout remains limited to category totals even when budget input is supplied.
  `[@test] ../tests/test_expenses_cli.py`

## Assumptions

- The format value is matched exactly and is case-sensitive; only lowercase `json` and `csv` are valid.
- Existing expense-file and budgets-file read errors and invalid budgets-file errors retain their established non-zero exit behavior; the format requirements apply after CLI arguments and required input files are valid.
- In CSV mode, `--budgets` remains accepted and its existing file-reading and parsing validation still applies, but budget alerts are not rendered because stdout is restricted to category totals.
- Optional flags use order-independent parsing, consistent with the existing `--month` and `--budgets` behavior.
- Supersedes py-20261004-6bjo REQ-13: optionally accepts `--month YYYY-MM` and/or `--budgets` and prints a JSON object becomes optionally accepts `--month YYYY-MM`, `--format json|csv`, and/or `--budgets`, defaults to JSON, and prints the selected format.
- Supersedes py-20261004-6bjo REQ-14: usage errors cover missing or invalid existing arguments and unrecognized optional arguments becomes usage errors also cover missing or invalid `--format` values.
- Supersedes py-20261004-16e2 REQ-14: usage errors cover missing or invalid positional, budget, and month arguments becomes usage errors also cover missing or invalid `--format` values.
- Supersedes py-20261005-kj6f REQ-9: positional and `--budgets` argument rules remain unchanged without `--month` becomes positional, `--budgets`, and `--format` rules remain unchanged without `--month`, with JSON as the default.
- Supersedes py-20261005-mwft assumption: Optional flags are parsed with order-independent semantics (equivalent to `argparse` optional arguments). becomes Optional flags are parsed with order-independent semantics (equivalent to `argparse` optional arguments); the supported flags are `--month`, `--budgets`, and `--format`.
- Runtime code uses the Python standard library only; no new third-party dependencies.
