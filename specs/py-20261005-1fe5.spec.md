# Expense CLI output format

- **REQ-1** Running `python -m factory_target_py.expenses` with a readable expense CSV and no `--format` option, or with `--format json`, prints exactly the same JSON output as the existing CLI for the same arguments, including the same keys, values, error records, month filtering, and budget-alert behavior, and exits with status 0 when the expense input file was read successfully.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** Running `python -m factory_target_py.expenses` with a readable expense CSV and `--format csv` prints to stdout a CSV document whose first line is exactly `category,total`, followed by one line for each category in the selected category totals, with each line containing the category and its total as a string formatted with exactly two decimal places.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-3** In `--format csv` output, category rows are ordered by ascending category name using plain string comparison, so for category names `Banana` and `apple` the output lists `Banana` before `apple` rather than using case-insensitive ordering.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** When `--format csv` is combined with `--month YYYY-MM`, the CSV contains only category totals for valid expense rows in that requested month; when the selected month has no valid expense rows, stdout contains only the `category,total` header.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** In `--format csv`, every invalid expense row reported by the importer is written to stderr as one line in the form `line <n>: <reason>`, preserving the importer error line number and reason and their order, no JSON is written to stdout, and the process exits with status 0 when the expense input file was read successfully.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** Any `--format` value other than `json` or `csv`, and `--format` without a following value, writes a usage message to stderr, writes nothing to stdout, and exits with status 1 without reading the expense file.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** The `--format` option can be supplied alongside `--month` and the existing optional CLI flags in any supported option order, and format selection does not change the validation of the expense CSV or the month value.
  `[@test] ../tests/test_expenses_cli.py`

## Assumptions

- `--format` is an order-independent optional flag like the existing `--month` and `--budgets` flags, and it may occur at most once.
- JSON remains the default format and its output is unchanged when `--format json` is explicit.
- CSV output renders the category totals selected by `--month`; it contains no JSON object or budget-alert section because the requested CSV document consists only of category totals.
- CSV category names are emitted as returned by the expense importer, and standard CSV field quoting is used if a category contains characters requiring quoting.
- CSV output uses the same two-decimal `Decimal` serialization as JSON output, including `ROUND_HALF_UP` handling already defined by the money formatting behavior.
- A readable expense file with invalid rows is still a successful CLI operation with exit status 0; unreadable expense or budgets files and invalid budgets content retain the existing non-zero error behavior.
- The `--format` usage message follows the existing CLI usage-message pattern; its exact wording is not part of the requirement.
- Runtime code uses only the Python standard library; no new third-party dependencies are required.
- End-to-end tests are out of scope for this task (`contract.e2e.applies` is false); CLI behavior is covered by unit-style subprocess tests under `tests/`.
