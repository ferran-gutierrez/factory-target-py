# Expense CLI output format

- **REQ-1** Running `python -m factory_target_py.expenses` with a readable expense CSV path and no `--format` flag prints to stdout the same JSON object as before this task (including optional `--month` and `--budgets` behaviour from prior specs) and exits with code 0 when the expense file was read successfully.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** Running with `--format json` explicitly produces successful stdout whose parsed JSON equals that from REQ-1 for the same expense file and combination of `--month` and `--budgets` flags.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-3** Running with `--format csv` and a readable expense CSV prints to stdout only CSV text: a first line exactly `category,total`, then one line per category in `category_totals` after any `--month` filtering, ordered by ascending category name using plain string comparison (Unicode code point order, so uppercase letters sort before lowercase), each line `<category>,<total>` where `<category>` is the expense canonical category key and `<total>` is the same two-decimal string that would appear in JSON `category_totals` for that key; no JSON is printed to stdout.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** For `--format csv`, when valid rows yield canonical categories `Banana` and `apple` with totals `1.00` and `2.00` respectively, stdout lines after the header are `Banana,1.00` then `apple,2.00` (plain string order), not `apple` before `Banana` as case-insensitive comparison would order them.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** When `--format csv` and `--month YYYY-MM` are both supplied, stdout CSV category lines reflect the same filtered `category_totals` as JSON output for that month (only spending in the requested month), while import validation still considers the full expense file.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** When `--format csv` and the expense file contains invalid data rows, the process exits 0 if the expense file was read, prints no JSON to stdout, prints each import error to stderr as exactly one line `line <n>: <reason>` using the same integer line number and reason string as the corresponding objects in JSON `errors`, and still prints the CSV header and any category total lines derived from valid rows.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** Running with `--format` as the last token (no value following), with `--format` followed by a value other than `json` or `csv`, or with an unrecognized optional argument, writes a usage message to stderr, prints nothing to stdout, and exits with status 1.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-8** When `--format csv` is used together with `--budgets` and a readable budgets CSV, stdout contains only the category-totals CSV (no `budget_alerts` or other JSON fields); unreadable budgets paths, budgets parse failures, and duplicate budget categories still follow the same stderr and exit-code rules as JSON output, with no successful CSV on stdout in those failure cases.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-9** Optional `--format`, `--month`, and `--budgets` flags may appear in any order after the expense CSV path; for example `--format csv --month 2024-05` and `--month 2024-05 --format csv` produce the same stdout CSV for the same files.
  `[@test] ../tests/test_expenses_cli.py`

## Assumptions

- Default output format is `json` when `--format` is omitted; `--format json` is accepted and equivalent to the default.
- CSV stdout includes only `category_totals` (after month filtering when `--month` is set); `month_totals`, `budget_alerts`, and the top-level `month` field are omitted from stdout in csv format but remain in json format as before.
- CSV category row order uses Python plain string sorting on canonical category keys (`sorted(category_totals.keys())`), not case-insensitive ordering used for budget alerts.
- stderr error lines for csv format use the format `line <n>: <reason>` with no JSON wrapping; multiple errors appear as multiple stderr lines in the same order as the `errors` list in json output.
- Usage messages for invalid or incomplete `--format` follow the same pattern as other CLI misuse (single usage line on stderr, exit code 1, empty stdout).
