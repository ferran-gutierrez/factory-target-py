# Expense CLI output formats

- **REQ-1** Running `python -m factory_target_py.expenses` with a readable expense CSV and no `--format` option produces the same JSON output as `--format json`, including the existing totals, errors, optional month field, and optional budget alerts, and exits with status 0.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-2** Running the expenses CLI with `--format csv` and a readable expense CSV writes to stdout a CSV document whose first line is exactly `category,total`, followed by one line for each category total, with categories ordered by ascending plain string comparison and each total represented as the same two-decimal string used for the corresponding JSON `category_totals` value.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-3** When `--format csv` is combined with `--month YYYY-MM`, the CSV output contains only category totals for valid expense rows in that selected month, using the same month filtering rules as JSON output; the header remains `category,total` and category ordering remains ascending plain string comparison.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-4** When `--format csv` imports a file containing invalid rows, it writes no JSON to stdout and writes one stderr line for each invalid row in the form `line <n>: <reason>`, preserving the line number and reason that would appear in JSON `errors`; after successfully reading the input file, the process exits with status 0.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** When `--format` is followed by a value other than `json` or `csv`, or when it has no following value, the CLI writes a usage message to stderr, writes nothing to stdout, and exits with status 1.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** The `--format` option can be supplied with the existing optional CLI flags, and its placement relative to `--month` does not change the selected month or format; JSON retains the existing complete output while CSV emits only the category-total CSV defined by this spec.
  `[@test] ../tests/test_expenses_cli.py`

## Assumptions

- `--format` is an optional argument accepted alongside `--month` and `--budgets`; `json` is the default when it is omitted.
- CSV output intentionally contains only category totals, so month metadata, import errors, and budget alerts are represented only through the CSV/error-stream rules in this spec rather than as CSV columns or records.
- CSV category ordering uses Python plain string ordering, which places uppercase letters before lowercase letters; category names are emitted using the canonical strings already used by the JSON totals.
- A readable expense file is a successful CLI operation even when individual rows are invalid; JSON reports those errors in its existing `errors` field, while CSV reports them one per stderr line.
- Runtime code uses the Python standard library only; no new third-party dependencies are required.
