# Expense CLI top categories

- **REQ-1** The package exposes `compute_top_categories(category_totals: dict[str, decimal.Decimal], n: int) -> list[dict]` in `factory_target_py.expenses` that returns at most `n` dicts, each with string keys `category` (an expense canonical category from `category_totals`) and `total` (the matching `decimal.Decimal` value), ordered by descending `total` and, when two categories share the same total, by ascending `category` using lexicographic string comparison on those canonical names; for `category_totals` `{"Travel": Decimal('20.00'), "Food": Decimal('30.00'), "Rent": Decimal('30.00')}` and `n` `2`, the returned list is `[{"category": "Food", "total": Decimal('30.00')}, {"category": "Rent", "total": Decimal('30.00')}]` (not `Travel`, which has the lower total).
  `[@test] ../tests/test_expenses_top_categories.py`

- **REQ-2** When `compute_top_categories` is given `category_totals` where `apple` and `Banana` each total `Decimal('10.00')` and `n` is at least `2`, the `apple` entry appears before the `Banana` entry because `"apple"` precedes `"Banana"` lexicographically even though uppercase `B` sorts before lowercase `a` in ASCII order.
  `[@test] ../tests/test_expenses_top_categories.py`

- **REQ-3** When `n` is greater than the number of keys in `category_totals`, `compute_top_categories` returns one entry per category (for example three categories and `n` `10` yields a list of length `3`).
  `[@test] ../tests/test_expenses_top_categories.py`

- **REQ-4** Running `python -m factory_target_py.expenses` with a readable expense CSV and `--top` followed by a positive integer `N` prints success JSON that includes `"top_categories"` as a JSON array of objects in the same order as `compute_top_categories` applied to the same `category_totals` map used for the printed `"category_totals"` (after any `--month` filtering), with each object’s `"total"` formatted as a two-decimal money string matching the corresponding `"category_totals"` entry.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-5** Running `python -m factory_target_py.expenses` with a readable expense CSV and no `--top` flag prints success JSON whose top-level keys are exactly those defined before this task for the same inputs (for example without `--budgets` or `--month`, keys remain `category_totals`, `month_totals`, and `errors` only).
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-6** When `--month YYYY-MM` and `--top N` are both supplied, `"top_categories"` ranks categories using the filtered `"category_totals"` for that month only; for example rows `2024-03-01,Food,A,50.00` and `2024-04-01,Travel,B,100.00` with `--month 2024-03 --top 1` yield `"top_categories": [{"category": "Food", "total": "50.00"}]` and no `Travel` entry.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-7** Running `python -m factory_target_py.expenses` with `--top` followed by `0`, a negative integer (for example `-1`), or a value that is not a positive integer (for example `abc`) writes a clear error message to stderr that states `--top` requires a positive integer, exits with a non-zero code, and prints no success JSON to stdout.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-8** Running `python -m factory_target_py.expenses` with `--top` as the last argument (no value following) writes a usage message to stderr and exits with a non-zero code.
  `[@test] ../tests/test_expenses_cli.py`

- **REQ-9** Optional `--month`, `--budgets`, and `--top` flags may appear in any order after the expense CSV path; for the same files and flag values, permutations such as `--top 2 --month 2024-05 --budgets budgets.csv` and `--budgets budgets.csv --top 2 --month 2024-05` produce identical success JSON payloads.
  `[@test] ../tests/test_expenses_cli.py`

## Assumptions

- `compute_top_categories` assumes `n` is a positive integer; CLI validation rejects non-positive and non-integer `--top` values before calling it.
- Tie-breaking on equal totals uses case-sensitive lexicographic order on expense canonical category strings (not case-insensitive comparison).
- When `category_totals` is empty, `--top N` still succeeds with `"top_categories": []`.
- Duplicate `--top` flags, repeated `--month` or `--budgets`, or unrecognized tokens after the expense path still produce a usage message on stderr and a non-zero exit, consistent with existing optional-flag parsing.
- Invalid `--top` values use a dedicated stderr error line (not the generic usage message) except when `--top` is missing its value, which follows the usage-message pattern used for `--month` and `--budgets`.
