- **REQ-1** `import_expenses(csv_text: str)` in `factory_target_py.expense_importer` returns a mapping with keys `by_category`, `by_month`, and `errors`; `by_category` maps category strings to `Decimal` sums, `by_month` maps `YYYY-MM` strings to `Decimal` sums, and `errors` is a list of mappings each with integer `line` and string `reason`.
  `[@test] ../tests/test_expense_importer.py`

- **REQ-2** The first non-empty line of `csv_text` is treated as a header row and is not validated or aggregated; data rows start on the following lines.
  `[@test] ../tests/test_expense_importer.py`

- **REQ-3** Each data row must contain exactly four comma-separated fields (standard CSV quoting rules via the library `csv` module); rows with any other field count are skipped and produce an error with reason `wrong column count`.
  `[@test] ../tests/test_expense_importer.py`

- **REQ-4** After trimming leading and trailing whitespace on each field, a data row with a `date` that is not a real calendar date in `YYYY-MM-DD` form is skipped and produces an error with reason `invalid date`.
  `[@test] ../tests/test_expense_importer.py`

- **REQ-5** After trimming, a data row with an empty `category` is skipped and produces an error with reason `empty category`.
  `[@test] ../tests/test_expense_importer.py`

- **REQ-6** After trimming, a data row with an empty `description` is skipped and produces an error with reason `empty description`.
  `[@test] ../tests/test_expense_importer.py`

- **REQ-7** After trimming, a data row whose `amount` is not a positive decimal number (must parse as a decimal strictly greater than zero) is skipped and produces an error with reason `invalid amount`.
  `[@test] ../tests/test_expense_importer.py`

- **REQ-8** For every skipped row, the reported `line` is the 1-based physical line number of that row in the original `csv_text` (including the header line as line 1 when present).
  `[@test] ../tests/test_expense_importer.py`

- **REQ-9** Valid data rows add their parsed `amount` to `by_category[category]` and to `by_month[YYYY-MM]` derived from the row date; multiple valid rows with the same category or month accumulate sums.
  `[@test] ../tests/test_expense_importer.py`

- **REQ-10** When `csv_text` contains a mix of valid and invalid data rows, `import_expenses` returns aggregated totals only from valid rows and an `errors` list containing one entry per invalid row with the correct line numbers and reasons.
  `[@test] ../tests/test_expense_importer.py`

- **REQ-11** Running `python -m factory_target_py <path>` reads the file at `<path>` as UTF-8 text, calls `import_expenses` on its contents, and prints a single JSON object to standard output with the same structure as the `import_expenses` return value (`by_category` and `by_month` values encoded as decimal strings, `errors` unchanged); non-zero exit status is not required on validation errors.
  `[@test] ../tests/test_expense_cli.py`

## Assumptions

- No `pyproject.toml` console script or entry point is added; the CLI is invoked only as `python -m factory_target_py` with one argument, the path to a CSV file on disk.
- The CSV uses comma delimiters and optional double-quote escaping per RFC-style CSV; fields are read with the standard library `csv` module.
- Header column order is `date`, `category`, `description`, `amount`; column names on the header row are not validated beyond skipping that row from aggregation.
- An input with no data rows (empty file or header only) yields empty `by_category`, empty `by_month`, and an empty `errors` list.
- Decimal aggregation uses `decimal.Decimal` internally; JSON CLI output represents monetary totals as strings to preserve decimal representation.
- Error reasons use exactly the literal strings specified in REQ-3 through REQ-7 so tests can assert stable messages.
